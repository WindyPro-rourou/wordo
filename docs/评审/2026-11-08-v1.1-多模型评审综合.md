> 交付前第 2 轮多模型评审（6 个视角 × 多模型并行）。原始逐模型意见见同目录
> `评审-algorithm-2026-11-08-08-38.md` 等 6 份。本文件是**综合与处置**，不是又一次评审。

## 评审设置与实况
- 视角（lens）：`algorithm`（学习科学）/ `ia`（信息架构）/ `mobile`（手机端）/ `consistency`（一致性度量）/ `extension`（可扩展性）/ `final`（交付终评）。
- 模型：`auto/glm-5.3-flash`、`auto/kimi-k3.1-pro`、`auto/deepseek-v4.1-flash`（经 magpie 网关直调，温度 0.4）。
- 实况：deepseek 全绿；glm 大部分返回；**kimi 多数超时**（网关侧不稳定，非本仓库问题）。下文「共识」指 ≥2 个有效模型或 deepseek+glm 同时命中。

## 共识（跨视角反复出现的 6 条）
1. **「结构一致率 100%」是门禁不是度量**：Schema 约束下必然接近 100%，应作为 CI 硬门禁；真正该量的主观字段（错因/置信度/inferred）需要人工 golden + kappa，且要有「自一致性噪声基线」作对照。
2. **首句自动判定学科后，用户确认/纠错要显眼**：判错会把整段对话、账本、SRS 挂错树，必须在判定处显式可改。
3. **今日页缺「目标 / 预计耗时 / 继续」总览**：学生打开第一问是「今天做多久、从哪开始」。
4. **空学科骨架不可用**：`scaffold_pack` 只给空壳，学生/老师还要跨到 CLI 才有内容，「建包 5 分钟、填内容卡 2 天」是弃用点；应内置**最小可用示例内容**或「粘贴一段文本→抽节点+题目」零档入口。
5. **学习科学参数与错因链路可再优化**：错因应从「标签」变成驱动出题/复习的硬约束；SRS 间隔建议绑定考试周期（考试锚点/绝对到期时间）。
6. **入库管线与极简节点的静默错误风险**：OCR 错字、引用漂移、设备时钟不可信、跨设备因果排序缺失——需要「待复核标记/批次可回滚/复合主键」。

## 已确认「其实已满足」（评审未看到、但仓库里已有）
- **学科判定后的显式提示与纠错**：M7 起，首句判定后追加系统提示「已根据这句话选定学科：…（命中原因）」，顶部学科胶囊可随时改（写事件、不改历史）。→ 采纳项仅是「把胶囊做得更显眼」，已在 v1.1 前端无障碍打磨中带过。
- **绝对到期时间戳**：账本事件与派生均用绝对 `due_ts`（ISO），`due_list` 按 `parseTs(due_ts) <= now` 过滤，**不是相对增量推算**。跨端读到同一账本即得同一队列。
- **每节点单调 seq**：每个节点只写自己的 `ledger/<node>.jsonl`，seq 在单文件内单调；合并按事件 id 去重。已用双节点并发 240 条验证 0 重复 / 0 缺口。
- **错因优先出题**：`due_list` 已把 `concept_confused` 排前。

## 采纳但排期（进入 `docs/路线图.md`，不在 v1.1 硬塞）
- 一致性：正式 kappa + 混淆矩阵 + 自一致性噪声基线 + 「决策状态机一致性」（同一 transcript 跨模型 SRS 状态转移一致率）。
- 学习科学：考试锚点 `exam_anchor`、错因→干预动作硬约束（概念错连补前置）、teach-back（费曼复述）判分。
- 内容：入库「零档」——粘贴一段文本 → 模型抽知识点+题目 → diff 预览 → 写入 `candidate/` 待审区。
- 多端/可靠性：桌面首启 `--diagnose` 自检（WebView2 版本/目录可写/账本完整性）；跨设备**因果排序**（设备 ID + 单调计数器复合主键 / 向量时钟）。

## 明确不采纳（附理由）
- **把置信度从「自评」改为「判分后追认/自动降权」**：会显著增加作答摩擦，且与现有「三档自评 + 蒙对不算掌握」的既有验证冲突；先作为路线图实验项，不在本轮改。
- **「删除结构一致率指标」**：不删，改为「门禁 + 明确口径」，保留可回归的 CI 事实。
- **让对话内判分不写 SRS、由今日页统一入账**：与「判分即落账」的已验证数据层（P1）冲突，回退成本高、收益不确定，拒绝。
