## 一、两家独立给出的**一致结论**（最高置信）

### 1. 环路主路径是断的：讲解后的检测题不落账（P1）
- 事实：`app.js` 的 `bindQuiz()` 在「非题库题」分支只改颜色 + `dataset.done=1`，**不调用任何记录接口**；`core` 侧也只有 `answer/delegation_out/delegation_result/plan_add/plan_done`，**从来没有 `explain` 事件**。
- 后果：最高频动作（看讲解→做检测题）对 mastery/薄弱/到期/错题/user.md 完全不可见，「记人/自进化」在核心路径上是空的。
- 已修：新增 `learn::record_judged`（合成 id，如 `english.high::kc_eng_0002::followup`）+ `learn::record_explain`（A3 留痕），API/Tauri/CLI/预览后端四端同构；前端讲解检测题与学习页 followup 均改为「判完即记」。实测账本出现 `source=chat-followup` 事件，界面显示「对/错 1/3 · 掌握度 37%」。

### 2. `chats/*.json` 整文件覆盖写 = 多设备静默丢会话（P2，最危险）
- 事实：读整文件→改→写回，无锁、无墓碑；id 为 `c<ms>` 无节点后缀（跨设备同毫秒撞 id）；删除是物理删除（同步后会被旧副本复活）。
- 两家都要求「会话也事件化」。
- 已修：`chats/<id>/<node>.jsonl` 每节点只追加 + `meta.json`；读时合并全部节点、按**解析后的时间戳**排序去重；删除写 `__deleted` 墓碑；重命名写 `__rename` 事件；id 带节点后缀。实测两节点合并 3 条消息顺序正确，删除后列表消失但文件仍在（可审计）。

### 3. 其他被点名的退化点（已修）
| 问题 | 修法 |
|---|---|
| `due_list` 永久排除「已掌握」→ 不再复习会遗忘 | 去掉 `!mastered` 过滤，保持性复习按间隔继续排 |
| `read_events` 用 RFC3339 字符串排序，跨时区错序 → streak/interval 全错 | 改为解析后按 UTC 毫秒排序（Rust + JS 都修） |
| `plan.md` 是多设备共写的单一文件，冲突副本会丢任务 | 计划改为**从账本 `plan_add/plan_done` 派生**，plan.md 降级 |
| `ask_model` 每次生成前重写 user.md（共享盘竞争写） | 改为**只在内存渲染**注入提示词，不写盘 |

## 二、两家都提、**尚未做**（下一轮）
