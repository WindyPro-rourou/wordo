# 评审（consistency）2026-11-08-08-48

## auto/glm-5.3-flash

**1. 结构一致率 100% 是个不构成信号的指标，先降级为门禁而非度量。**
Schema 校验在 JSON mode / few-shot 约束下几乎必然通过，100% 说明的是“接了约束”，不是“模型能力趋同”。它该有的位置是 CI 硬门禁（fail 即阻断），真正要度量的是它背后的东西：字段级合法率（比如 错因 枚举值是否落在规范内 vs 空串/null）、触发重试的比例、golden 用例一次通过率。如果 20 个 golden 里 3 个要重试才过 schema，这个信息目前被 100% 掩盖了。

**2. 主观字段缺一致性度量学科里的标准做法：kappa，不是“统计对了多少”。**
错因分型、置信度、inferred 这些是分类任务，正确指标是 Cohen's kappa（两模型）或 Fleiss kappa（≥3 模型）对 golden 标注集算一致度，并输出混淆矩阵——尤其要看 错因 各分型之间模型怎么互相漂（比如 “概念混淆” 被另一个模型标成 “审题失误”，这种系统性偏移比整体一致率重要得多）。golden 集要分层抽样：按学科 × 题型 × 错因类型，每格有最低样本量（建议 ≥20/格），否则单格 kappa 置信区间宽到没法决策。

**3. “目标”的定义缺一个噪声基线：模型自一致性。**
没有它，任何跨模型数字都无法解读。正确做法：同一模型同 prompt 跑 N 次（温度按生产设置），得到 intra-model 一致率——这是理论天花板。跨模型 kappa 达到“自一致率的 85-90%”才是有意义的“趋同”定义；低于它说明差异来自模型本身，高于它说明你的指标不敏感。当前文档里“结构一致率 100%”没有对照组，等于没定义目标。建议在 DEVELOPMENT 里写死验收式表述：“跨模型主观字段 kappa ≥ 0.7 且 ≥ 自一致率 × 0.85，结构字段零重试通过率 ≥ 95%”。

**4. 缺行为级/结果级一致性，目前只量了“标签”没量“后果”。**
多模型趋同的最终判据是：同一个学生 transcript 喂给不同模型，后续学习轨迹是否一致——SRS 间隔决策、掌握/不掌握判定、“连续两错→换讲法”触发是否一致。字段级 kappa 高但 掌握判定 边界不同，学生换设备/换模型后复习队列就分叉，这才是用户可感知的失效。建议加一个 transcript 回放测试：固定一批脱敏账本，断言各模型产出的 SRS 状态转移一致率 ≥ 95%。另外两个缺口：① prompt/subject-pack 版本与模型版本的配对记录（换模型后历史 kappa 数字失效，要能重跑对比）；② 一致性和正确性是两回事——两个模型一致地给错错因不算趋同，golden 标注必须由人工裁决做 ground truth，不能拿单一强模型当裁判后循环论证。

## auto/deepseek-v4.1-flash

针对「跨模型一致性度量」的专项评审，结合 WORDO 现有架构（账本、学习科学规则、Golden 回忆）与多模型切换的实际情况。直接给结论：**“结构一致率 100%” 是虚胖，“主观字段分离”是方向对但缺乏度量标尺，目前没有任何指标能证明“多模型趋同”。**

以下 4 条具体评审意见：

### 1. 结构性分离合理，但“100%”是伪命题，应立即改为“Schema 强制校验（通过/不通过）”
**现状批判**：将 JSON Schema 结构件与主观字段（错因/教具/inferred）分开统计，在逻辑上完全正确（因为结构 99% 由 Prompt 模板和 Pydantic Schema 锁定，主观字段 100% 由 LLM 自由生成）。但**“结构一致率 100%” 没有任何增量信息**——它是“必须达到”的底线，不是“值得跟踪”的指标。如果某天掉到 98%，说明的不是模型差异，而是你的系统 Prompt 被用户改坏了或 Rust 解析逻辑有 Bug（这在你的账本/自检机制下应直接硬报错）。
**执行建议**：删除“结构一致率”这个量化指标，改为 **`Schema 合规性（布尔值，Gate）`**。只有合规样本才进入主观字段评测，不合规样本直接算作“该模型批次测试失败”。

### 2. 主观字段一致性本该“追求语义等价”，而非“追求字面趋同”；当前缺量化 Golden 阈值
**现状批判**：你目前只是“拆分”了主观字段，但没有定义“拆开后怎么算一致”。如果用户对同一错题，模型 A 输出 `错因: 概念混淆（映射混淆）`，模型 B 输出 `错因: 对公式适用条件不清`——这算不一致吗？在人类教师眼里，这两者高度趋同（都属于“理解偏误”），但在你的文本对比里这算 0 分。
**执行建议**：
- 针对**错因/教具**字段，禁用 `exact_match`，改为**“层次化模糊匹配”**。基于你现成的 `subject-pack` 内置的错因分型（如 理解偏误/计算错误/审题偏差），定义**父类一致率 ≥ 90%** 才算趋同。例如：只要两个模型都落在 `错因[一级类]`，就视为一致；子类允许分歧。
- 针对 **inferred（置信度推断）** 字段，它不是“趋同”指标，而是“校准”指标。应该对比的是**模型的 inferred 与“用户自我报告置信度”的方差**。两个模型给出的 inferred 不同但都准确，比两个模型相同但都错误更有价值。**别问它们是否一致，要问谁更准。**

### 3. 目标定义空洞：缺“行为一致性”（跨模型对学习科学的规则触发），而非单纯“输出一致性”
**缺失什么（这是核心）**：WORDO 的核心卖点是 **学习科学规则**（连续两错→换讲法；蒙对不算掌握）。目前的结构+主观字段评测，只测了“一次性问答”，**根本没测“跨模型在动态学习流程中的决策一致性”**。要求“趋同”的定义应该是：**在相同的教学情境下，不同模型必须触发相同的业务规则（状态机），而业务规则触发的依据（即 LLM 的推理结果）允许有措辞差异。**
**执行建议**：增加一个 **`决策状态机一致性率`** 指标。
- 设计 20 个 Golden 历史对话（模拟连续两错的场景），输入给不同模型，观察它们输出的**行为动作**（是 `重讲` 还是 `直接讲下一题`？是 `降低掌握度` 还是 `增加复习`？）。
- 判定标准：状态机流转结果一致即得分。**只有这个指标 ≥ 95%，你才能毫无负担地在多模型服务间做负载均衡，否则用户换个模型，学习体验就直接断崖。**

### 4. 还缺“跨模型语境稳定性”：当前所有评测均为“单发无状态”，无法支撑对话历史与自进化
**补充缺失项**：你的架构是 append-only 账本（对话历史事件化存储），且强调 `user.md` 由账本派生。当前评测完全忽略了**“给定同一段历史账本，模型能否承接/续写”**。很多模型对短 Prompt 时表现很好，一旦上下文变长（超过 20 轮、含错题历史），A 模型能继承之前的“教具偏好”，B 模型则可能假设用户是一张白纸，输出与历史冲突。
**执行建议**：将评测从**单轮**升级为**序列评测**。
- 从你的测试语料库切出 50 组**真实带账本历史的上下文**（包含交错练习、confusion 标记）。
- 评测指标：检测新轮次的输出是否与“老账本”中隐含的知识状态**自洽**（例如用户上一轮对三角函数标记“说不准”，这轮模型不能直接假设用户已掌握来出进阶题）。
- **只有通过此评测，才能支撑你说的“自进化”概念，否则多模型切换必然导致账本污染。**

---

**一句话总结**：你们的“结构/主观分离”是好的数据卫生习惯，但**离“多模型效果趋同”还有 3 个量级的差距**。请把焦点从“一句话的格式化输出”转移到：(1) 语义层级一致性；(2) 学习规则状态机一致性；(3) 长上下文状态承接一致性。这三者全部通过，才能宣称“跨模型趋同”。
