## ① 一句话结论

**用户原始计划（爬教材原文 + 爬出卷网/学科网/菁优网题库，随多端 App 分发）＝🔴 高风险，不建议走。**

三个独立的致命点，任一成立都足以否掉这条路：

1. **教材原文受著作权保护**，且平台型资源（国家中小学智慧教育平台）**只取得「信息网络传播权」，不含「复制权」「发行权」**——「在线免费看」≠「可以下载当储备数据」≠「可以再分发」（`✅ 一手`，见 §3）。
2. **成套题库已被生效判例认定为「汇编作品」**，且法院明确否定了「公有领域」「法定许可」抗辩（最高检刊文，`✅ 一手`，见 §2）。商业题库平台的服务条款**逐家明文禁止**「以软件程序自动获得数据」与任何复制/再分发（`✅ 一手`，本次实测）。
3. **规模化抓取 + 破解反爬**有刑事先例：「今日头条案」（晟品公司）被告人以**非法获取计算机信息系统数据罪**获刑，法院认定的核心是「规避或突破安防措施、未经许可进入计算机系统＝侵入」（`✅ 一手`，判决书案号见 §2）。

**推荐替代路径**：以**官方/开放许可资源为知识源**（只在线引用、不入库、不再分发）→ 用 **LLM 依公开知识点生成题目 + 答案自动校验 + 人工抽检** 构建**自产题库** → 本地**只存「知识点树 + 外部资源索引 + 自产题 + 用户笔记」**。这条路径同时满足合规、离线、P2P 分发与 ESP32 端轻量化的全部需求（详见 §5 路径 A／C）。

### 2.1 教材版权的先验判断（部分待核实）

- 现行《著作权法》为 2020-11-11 修正、**2021-06-01 施行**；第24条列举合理使用情形，含「(一) 个人学习、研究或者欣赏」「(六) 为学校课堂教学或者科学研究，翻译、改编、汇编、播放或者少量复制已经发表的作品，供教学或者科研人员使用，**但不得出版发行**」，并在条首设「指明作者姓名或者名称、作品名称，且不得影响该作品的正常使用，也不得不合理地损害著作权人的合法权益」的三步检验约束（`✅ 一手`，[WIPO Lex](https://www.wipo.int/wipolex/ar/legislation/details/21065)、[检察系统转载](http://www.changchunly.jcy.gov.cn/flsd/202501/t20250124_6810262.shtml)）。
- 中小学教材一般为**法人作品/职务作品**，由出版社（如人民教育出版社）组织编写；法人作品保护期为**首次发表后 50 年**，自然人作品为作者终生+死后 50 年（`❓ 待核实`官方条文链接——本次未取得直接条文页，正式文档需补）。
- 教材的**整体编排**还可构成汇编作品；教材中**单篇课文**另有各自作者与保护期；出版方可能另行主张**版式设计专有权**。三者叠加（`⚠️ 二手`，法律通说，待律师确认）。
- **关键边界**：「个人学习使用」豁免的是**你自己学**；一旦变成**向他人提供/公开分发**（App 分发、P2P 网络共享、多端同步给他人），即落入复制权+信息网络传播权，第24条(六)的「不得出版发行」是硬约束。

### 2.2 题目的版权

- **单题是否构成作品看独创性**：纯事实/公式化题（「1+1=?」「水的沸点」）独创性极低；有原创情境与设问设计的题目可构成作品（`❓ 待核实`具体判例）。
- **成套题库已被认定可构成汇编作品**——这是最有分量的结论。最高检刊载文章明确：涉案公司题库「在试题内容的选择、编排上具有独创性，可以认定为著作权法意义上的『汇编作品』」，且「本案也不存在『公有领域』『法定许可』等违法阻却事由」（`✅ 一手`，[spp.gov.cn](https://www.spp.gov.cn/llyj/202304/t20230422_612060.shtml)）。**这直接否掉了「题目都是公开的所以能爬」这一常见误解。**
- **答案与解析**通常是**独创性最高**的部分（讲解是原创表达），比题干更易被认定侵权。即使只搬「解析」也危险。
- 中国法上**没有**欧盟式的独立数据库特别权利（`sui generis` database right），数据库保护主要靠「汇编作品 + 反不正当竞争」双轨（`❓ 待核实`）。

### 3.1 国家平台的核心法律细节（本项目最容易被误判的一条）

- **「免费使用」≠「可下载再分发」。**《浙江教育报》2026-10 文章指出：「国家中小学智慧教育平台上的数字教材版权并不完全属于平台，而是归属于各出版机构。平台从资源提供者那里获取的是『**信息网络传播权**』，**不包含『复制权』和『发行权』，用户无权下载和传播**」（`⚠️ 二手`，[浙江教育报数字报](https://epaper.zjjyzx.com.cn/html/2026-10/09/content_155853_3902841.htm)）。
- 该表述与**一手证据完全吻合**：某高校公示的平台资源**授权书样本**中，权利人授予的正是「**信息网络传播权**——将该作品发布于国家智慧教育公共服务平台……供平台用户**在线阅览，不可下载**」（`✅ 一手`，[授权书附件](https://jwc.hgu.edu.cn/system/_content/download.jsp?urltype=news.DownloadAttachUrl&owner=1228123190&wbfileid=14927184)）。
- **对本项目的直接含义**：即使用户「只用官方平台」，也**不能**把平台教材 PDF 批量下载进本地知识库、更不能随 P2P 网络分发。**只能做「链接 + 元数据索引」**（跳转到平台在线查看）。
- 另有报道称海南等地区开放了备课资源 **DOC 下载**（2026-03）（`❓ 待核实`原文——本次未取得，正式发布前需补）。

### 3.2 一个值得注意的细节：robots 的「分区放行」

三家平台的 robots 实测显示出**完全不同的态度**，这本身就是重要情报：

| 平台 | robots 对「内容/题目」目录的态度 |
|---|---|
| 菁优网 | **放行**：`Allow: /shijuan/*`、`/shiti/*`、`/pp/*`（面向搜索引擎索引） |
| 学科网 | **收紧**：`Disallow: /*?*`（带参数页全禁）、`/book`、`/20*`（年份归档） |

## ⑤ 推荐的三条数据路径（按合规性排序，附成本与质量）

### 路径 A（**首选**）：官方资源在线引用 + LLM 自产题 + 人工校验
- **做法**：知识树来自**公开课标/知识点名称**（自行整理，不照抄他人独创性编排）；教材内容**只存「链接 + 定位 + 摘要性元数据」**，用户点开跳转官方平台在线看；题目**全部由 LLM 依知识点生成**，理科题用可执行校验（代入求解/单位检查）自动判错，文科题人工抽检。
- **合规**：🟢 低。不复制受保护表达、不再分发第三方内容。
- **成本**：中。主要成本是「生成 + 自动校验 + 人工抽检」的算力与人工；单题边际成本随规模下降。
- **质量**：可做到中上；**必须**有校验层，否则会出现答案错误（这是 LLM 出题最大隐患）。
- **对多端/P2P/ESP32 友好度**：✅ 最高——数据是自产的，可自由分发、可离线、可裁剪进 ESP32。

### 路径 B（**次选**）：正规授权 / 开放许可数据集
- **做法**：向学科网等购买机构内容授权或 API；采用**明确允许再分发**的开放许可资源（如 OpenStax CC BY 4.0；Khan Academy 仅限非商业）。
- **合规**：🟢/🟡 —— 取决于合同范围。**授权合同必须写清**：可否缓存、可否离线、可否经 P2P 分发、可否二次改编、地域与期限。
- **成本**：🔴 高（商业授权费用量级本次**未取得公开信息，标待核实**）。
- **质量**：高（专业题库质量通常优于模型生成）。
- **风险**：授权范围与产品形态冲突（P2P 分发几乎肯定超出常规授权范围，需特别谈判）。

### 路径 C（**降级兜底，永远可行，且必须做**）：只存「知识点 + 索引 + 自产题 + 用户笔记」
- **做法**：本地库只包含 ① 自建知识点树；② 外部资源**指针**（URL/平台 ID/标题/在章节中的位置）；③ 自产题目；④ 用户自己录入的笔记与题目。
- **合规**：🟢 最低。**不含任何受版权保护的第三人内容**。
- **成本**：低（数据量小，无抓取与清洗成本）。
- **质量**：依赖路径 A 的生成质量 + 用户自产。
- **关键价值**：这是唯一**同时满足**「合规」「离线」「P2P 网络分发」「ESP32 端可承载」的架构。**建议把它作为本项目的基线架构**，A、B 只是往这个骨架里灌内容的两种方式。

## ⑥ 数据工程管线建议（含 schema 设计）

### 6.1 原始资料解析管线
- **优先级**：结构化文本层 PDF（直接抽取） > EPUB/HTML > 扫描件（才用 OCR）。
- **版面分析是准确率瓶颈**：分栏、表格、图注、页眉页脚必须用 layout 模型处理，纯 OCR 不够。候选（许可需逐一核实）：MinerU（AGPL-3.0，`❓`）、IBM Docling（MIT，`❓`）、Marker（GPL 系，`❓`）、Unstructured（Apache-2.0，`❓`）、PyMuPDF（AGPL，`❓`）——**⚠️ 注意本项目若是闭源/商业，AGPL/GPL 工具链本身也会带来合规约束**（参见本目录 `07-许可合规速查.md`）。
- **中文 OCR**：PaddleOCR（Apache-2.0，生态成熟，`❓ 待核实当前许可证`）为首选；公式另用专用模型（pix2tex/LaTeX-OCR 等）；高精度商用可考虑 Mathpix（付费）。
- **⚠️ 管线合规前提**：**解析管线本身合法，但喂给它的输入必须合法**。管线不能洗白输入来源。

### 6.2 题目结构化 schema（建议）

```jsonc
{
  "id": "q_<sha1_16>",              // 内容寻址，便于去重与联网同步
  "origin": {                        // 来源与授权（合规审计必需）
    "type": "generated | user | licensed | public_domain",
    "model": "deepseek-xxx",         // type=generated 时记录
    "prompt_hash": "…",
    "license": "project-owned | CC-BY-4.0 | …",
    "redistributable": true,         // ← 决定能否进 P2P 网络
    "source_ref": null               // 仅指针，绝不存第三方原文
  },
  "curriculum": {
    "subject": "math", "grade": 5, "edition": "人教版",
    "chapter_path": ["数与代数", "分数的意义", "通分"],
    "knowledge_tags": ["k_frac_add_hetero"]
  },
  "stem":        { "format": "markdown+latex | plain", "text": "…" },
  "options":     [ { "key": "A", "text": "…" } ],   // 可为空（填空/解答）
  "answer":      { "type": "choice | blank | numeric | proof", "value": "B" },
  "explanation": { "text": "…", "generated": true },
  "verification": {                  // ← 质量的命门
    "method": "executable | llm_judge | human",
    "checked_at": "…", "passed": true, "human_reviewed": false
  },
  "media":   [ { "kind": "image|audio|formula", "hash": "…", "path": "…" } ],
  "difficulty": { "scale": "irt_b | elo", "value": 0.42 },
  "stats":   { "attempts": 0, "correct": 0 },   // 本地统计，不上传
  "hash": "…", "version": 1, "updated_at": "…"
}
```

**要点**：`origin.redistributable` 与 `verification` 两个字段是整个合规与质量体系的开关——建议在代码层强制：`redistributable=false` 的记录**不允许**进入任何同步/导出代码路径。

### 6.3 知识点标注
- 三级递进：**规则匹配**（关键词表，快但覆盖窄）→ **向量检索近邻**（把题目 embedding 与知识点描述做近邻，覆盖率好）→ **LLM 闭集分类**（给定候选知识点集合让模型选，最可控、准确率最高）。
- 工程上建议**三者投票 + 置信度阈值**，低置信度进人工队列。
- 准确率与人工成本需实测（`❓ 待核实`具体数字），建议先用 500 题样本做一次标注一致性实验再定流程。

### 6.4 落库与版本化
- **选型**：单机多端 **SQLite（含 FTS5 全文检索）+ JSON 导入导出** 是性价比最高的组合；向量检索可用 `sqlite-vec` 或本地索引文件。规模上来后再考虑 PostgreSQL/文档库。
- **增量更新**：以 `hash`（内容寻址）为主键，新增即插入、变更即新版本，用 `updated_at` 做增量同步游标。
- **去重**：两层——**近似重复**用 MinHash/LSH 或 SimHash（抓「同题多来源」）；**语义重复**用 embedding 余弦相似度（抓「换数字的同一道题」）。对「自产题 + 授权题 + 用户题」混合库尤其必要。

## ⑦ 坑与风险

1. **🔴 最大坑：「免费」被误读为「可下载可分发」。** 国家平台的授权书原文写的是「在线阅览，**不可下载**」——如果照原计划把平台教材抓成本地储备资料，**第一步就已经越界**。
2. **🔴 robots.txt 不是许可。** 菁优网 robots 明确 `Allow: /shiti/`，服务条款却全面禁止复制散布。**「robots 允许」不能作为合规依据**，反之违反 robots 会成为不正当竞争的不利因素（百度诉 360，判赔 70 万）。
3. **🔴 「题目是公开的所以能爬」是错误认知。** 生效判例已认定题库构成**汇编作品**，并明确否定「公有领域」「法定许可」抗辩。
4. **🟠 反爬即是红线。** 晟品案的关键不是「抓了数据」，而是「**规避或突破安防措施**」被认定侵入。一旦引入验证码识别、UA/Cookie 伪造、代理池绕封禁，风险从民事跳到**刑事**。
5. **🟠 高频抓取可能被认定为破坏服务**（反法互联网专条，罚 100–500 万；严重时刑法 286 条）。
6. **🔴 未成年人数据是本项目自带的合规负担。** 学生答题记录、错题、学习画像属于个人信息，不满 14 周岁须监护人同意 + 专门规则。**建议架构上「本地优先、绝不上传原始答题数据」**，P2P 场景尤其要注意——**用户笔记/题目上链或跨用户共享时，必须先在用户协议里取得明确的、可撤回的分发授权**。
7. **🟡 工具链许可的二级风险。** 解析工具若是 AGPL/GPL（MinerU、PyMuPDF、Marker 等），会把许可义务带进本项目——见本目录 `07-许可合规速查.md` 的三档原则。
8. **🟡 生成内容的相似度风险。** LLM 出题若与训练语料中的原题高度相似，仍有侵权可能；需要**与已知题库做相似度过滤**（MinHash/embedding）作为出厂检查。
9. **🟡 「知识树」本身也可能被主张汇编权。** 如果知识点层级是照抄某平台/某教辅的独创性编排，仍有风险；建议基于**课标原文**自行构建层级。
10. **⏱ 前一个 agent 的教训**：本类调研极易陷入「只检索不落盘」。**先落骨架、增量写回**是硬纪律（本文即按此执行）。

## ⑧ 对本项目的 5 条可落地建议

1. **立刻放弃「爬教材原文 + 爬题库」的原始计划**，把 §5 路径 C（知识点+索引+自产题+用户笔记）定为**基线架构**——它是唯一能兼容「去中心化 P2P 分发 + 离线多端 + ESP32 轻量端」且合规的形态。
2. **把 `origin.redistributable` 写进 schema 并在代码层强制**：非自产/无明确再分发授权的数据**在技术上无法**进入同步与导出路径。合规做成**结构性约束**，而不是流程性约定。
3. **知识源走「在线引用」而非「本地囤积」**：国家平台等资源只存 URL + 章节定位 + 客观元数据，用户点开跳转官方平台在线看；既合规又不破坏官方平台的流量与权益。
4. **题目走「LLM 生成 + 自动校验 + 人工抽检」三段式**，并把「可执行校验」（理科题代入求解、单位/量纲检查）作为**出厂门槛**；同时用 MinHash/embedding 与已知题库做**相似度体检**，防止无意复现原题。
5. **未成年人数据默认本地、默认不共享**：答题/错题原始记录只留在用户设备；若要 P2P 共享用户自产内容，必须在用户协议中写明授权范围、撤回方式，并为不满 14 周岁用户设置监护人同意流程与专门的个人信息处理规则。

### A. 法律与合规
- **已证实**：教材/题库权利归属复杂、平台免费≠可分发、题库构成汇编作品、robots 非授权、反爬有刑事风险、未成年人数据须专门规则。
- **未核实**：教材法人作品保护期条文链接、数据库特别权利、单题独创性的具体判例、AI 生成内容权利归属判例原文。
- **反不正当竞争法互联网专条的历史沿革**：2017 年修法新增「互联网专条」，2025 年修订后为**第13条**并新增第4款（网络恶意交易）——2025 年版条文与处罚幅度已由《人民日报》《人民法院报》证实。

### B. 合法替代
- **推荐优先级**：自产题（LLM+校验）> 明确可再分发的开放资源（OpenStax CC BY）> 授权采购 > 只存指针的降级方案。
- **英文世界开放资源多、中文 K12 可再分发资源极少**——这是本项目必须面对的现实：**中文教材/题库的开放许可生态基本不存在**，因此「自产」几乎是唯一可规模化的合规路径。

### C. 数据工程
- 解析管线的合规前提（输入必须合法）比技术选型更重要。
- `redistributable` + `verification` 双字段是合规与质量的开关。
- 去重必须做「近似 + 语义」两层。

## ⑩ 爬虫红线速查（工程执行层，一票否决项）

> 若团队中仍有人主张「先爬了再说」，请让他先逐条回答下列问题。**任一为「是」即应立刻停止**。

| # | 检查项 | 若为「是」 | 依据 |
|---|---|---|---|
| 1 | 目标站 robots.txt 是否 Disallow 了你要抓的路径？ | 🔴 停 | §3（组卷网已明确 Disallow 学科目录） |
| 2 | 目标站条款是否禁止「以软件程序自动获得数据」？ | 🔴 停 | 学科网版权声明原文 |
| 3 | 是否需要登录/Cookie/伪造 UA 才能拿到内容？ | 🔴 停（刑事风险上升） | 刑法285条、晟品案 |
| 4 | 是否涉及验证码识别或反爬绕过？ | 🔴 **立即停**（「侵入」认定的核心） | (2017)京0108刑初2384号 |
| 5 | 抓取结果是否会被**再分发**（App 分发 / P2P 共享 / 多端同步）？ | 🔴 停 | 复制权+信息网络传播权 |
| 6 | 抓取的内容是**成套试卷/题库**（而非零散事实）？ | 🔴 停（汇编作品） | 最高检刊文 |
| 7 | 是否包含**答案与解析**的完整文本？ | 🔴 停（独创性最高） | §2.2 |
| 8 | 是否有高频/并发请求可能影响对方服务？ | 🟠 改 | 反法第13条 |
| 9 | 是否触碰未成年人个人信息？ | 🔴 停（须监护人同意+专门规则） | PIPL 第31条 |
| 10 | 解析工具是 AGPL/GPL 且本项目闭源商用？ | 🟠 改 | 见 `07-许可合规速查.md` |

**唯一安全的技术姿势**：`只取「是否存在/标题/链接/定位」这类事实性元数据，不取表达性内容；低频、遵守 robots、不绕任何技术措施、结果不入库不再分发。`而即使这样，「低频抓元数据」的收益也远小于直接让 LLM 依知识点生成题目——**所以对本题而言，爬虫在经济上也是不划算的**。

## ⑫ 结论复核：原始计划 vs 推荐方案

| 维度 | 用户原始计划（爬教材+爬题库） | 推荐方案（路径 A+C） |
|---|---|---|
| 合规性 | 🔴 高（侵权 + 反法 + 刑事 + 未成年人四重风险） | 🟢 低 |
| 起步速度 | 「看起来快」，实则卡在合规评审 | 需先建生成/校验管线，起步稍慢 |
| 数据质量 | 高（真人命题）但**不可用** | 中上，靠校验层保证 |
| 可再分发（P2P 必需） | ❌ 不可能 | ✅ 可以 |
| 离线/ESP32 适配 | 体积大、版权随包走 | ✅ 轻量、干净 |
| 长期可持续 | 随时被投诉/下架/追责 | 自主可控，可积累数据资产 |
| 法律成本 | 潜在赔款（判例 70 万 / 323 万量级）+ 刑事风险 | 一次律师咨询费 |

**最终判断**：原计划的「**目标**」（按章节组织、生成完整知识树）完全正确且必须做；错的只是「**手段**」（爬取受保护的第三方内容）。把手段换成「公开知识点 + 自产题 + 在线索引」，**目标不变、风险归零、且更适配去中心化 P2P 架构**。
