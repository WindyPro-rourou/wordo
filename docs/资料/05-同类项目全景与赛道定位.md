## 一、一句话结论

**这个赛道的四块拼图（去中心化训练、智能体自进化、跨平台多设备运行、学习闭环）每一块都已有成熟的独立方案，但「把四块缝成一个能长期跑、且真的会变强」的完整系统，目前只有 Continuum 一个项目在认真做，且它自己承认最大的命题仍是未解的科研问题。**

所以本项目的定位不应该是「再造一个去中心化训练框架」（会死在入网上），而应该是：
**在已验证的碎片之上，做一个「单人/小团队就装得起、跑得起来、看得到进步」的最小自进化闭环**——重学习闭环与可验证性，轻底层训练创新。

## 二、赛道地图：四个正交维度

把「去中心化分布式跨平台自进化 AI 学习系统」拆成四个可独立评估的维度，每个维度标出当前 SOTA 与成熟度：

| 维度 | 核心问题 | 当前 SOTA | 成熟度 | 个人可否落地 |
|---|---|---|---|---|
| **① 训练去中心化** | 多台异构设备能否协同训练一个模型？ | DiLoCo / OpenDiLoCo / DisTrO / DeMo / SparseLoCo | 研究可用、工程脆弱 | 通信可（家用带宽），收敛性存疑 |
| **② 智能体自进化** | 系统能否基于经验自动变强？ | DGM / SEAL / Absolute Zero / SkillEvo | 论文级、单机可复现 | ✅ 最可落地的一环 |
| **③ 跨平台多设备运行** | 一个「心智」能否跨设备常驻并协作？ | Continuum Grid / GSV(Ship) / Iroh / libp2p | 工程可用 | ✅ 已很成熟 |
| **④ 学习闭环（人 or AI）** | 学习效果如何量化、如何不遗忘？ | FSRS / DKT / MAP-Elites 归档 | 学习科学成熟、AI 侧不成熟 | ✅ 有成熟算法 |

**关键判断**：维度 ① 是**最危险**的投入方向（学术指标好看、个人设备上难复现）；维度 ②④ 是**最高性价比**的方向（单机即可验证、效果可测量）；维度 ③ 是**必要但无聊**的基建（直接用 Iroh/libp2p 即可，不要自研）。

## 三、同类项目对照（开源，重点看）

### 3.1 直接对标：Continuum（CambrianTech）

- 仓库：<https://github.com/CambrianTech/continuum> ｜ 许可：AGPL-3.0（原 MIT，2025-11-05 切换）｜ 状态：**pre-alpha**（作者自述 "Expect sharp edges"）
- 核心主张：**「模型不是存在（the model is not the being）」**——身份/记忆/经验/技能依附于 Citizen（持久智能体），模型只是可替换的认知器官。
- 四条闭环：`认知循环` + `记忆` + `基因组(Genome)` + `网格(Grid)`，即 **live → experience → learn → evolve → distribute**。
- 关键机制：
  - **经验→权重**：工作产生经验 → 暴露能力缺口 → 缺口变课程 → Academy 训练 LoRA → 效果再检验 → **adopt / reject**。明确声明「训练完成不等于学到」（candidate adaptation has to earn adoption）。
  - **失败即训练数据**：编译器报错、测试失败、grader 否决、同伴纠正 = 「意图与能力之间被标注的缺口」。
  - **Gene / Genome 隐喻**：LoRA 适配 = 基因（带 provenance 与血统），组合 = 基因组，表现 = 表型；个体学习 → 种群演化。
  - **Grid（学习网格）**：强机器训练 gene → 发布 → 弱机器发现并继承；跨设备传的是**适配器而非整个基座模型**。作者实测节点：RTX 5090 (32GB) 跑 Qwen3.8-27B Q4_K_M，单车道 70k 窗口，一小时 46 acts；MacBook M5 Pro (64GB) 双车道 67k，一小时 11 acts。
  - **Forge-Alloy**：把模型工作当可复现契约——记录预期/实际/产物/hash/评估/硬件/密码学证明。「recipe becomes the receipt」。
  - **资源经济学**：把认知当稀缺资源治理（KV-slot 经济、模型分页、内存压力可否决分配）——「本地优先不是本地唯一」。
- 技术栈：headless **Rust core** + 内置 llama.cpp/whisper.cpp submodule + SQLite 单存储 + Web/移动/CLI/MCP 多客户端 + Positron 统一定义层（同一应用定义投影为 Web UI / 原生 / persona 语义面）。
- **作者亲自标注「仍未知」的三个科研问题**（对我们极其重要，等于替我们划出了风险区）：
  1. 累积的**真实经验**能否带来长周期能力提升？
  2. **独立学到的 gene 之间能否良好组合**？（水平转移何时帮忙、何时干扰）
  3. 在**同等算力与工具预算**下，持久化居民群体能否胜过无状态系统？以及多少身份能跨越不同认知基座存活？
- 对我们的意义：**这是唯一一个把「人格持续 + 经验转权重 + 跨设备继承」全串起来的开源实现，必须精读；但它 pre-alpha、AGPL、体量巨大（~29.5k 行刚被重构过），不适合直接 fork 当基座，适合当架构参照与 vocabulary 来源。**

### 3.2 直接对标：Skill 层自进化 —— AutoSkill / SkillEvo（ECNU-ICALK + 上海 AI Lab）

- 仓库：<https://github.com/ECNU-ICALK/AutoSkill> ｜ 论文：arXiv:2603.01145（`Experience-driven Lifelong Learning (ELL)`）
- 核心主张：从**真实交互经验**中提取可复用技能，写成人类可读可改的 `SKILL.md`，并用 **merge + 版本更新**持续演化（v0.1.0 → v0.1.1），而不是每次新建。
- 关键设计（非常适合借鉴，成本极低）：
  - **不去噪就不建技能**：用户只泛泛说「写个报告」→ 不创建技能（输出空结果），避免产生垃圾技能；只有当出现**持久约束**（如「不要编造」）时才提取。
  - **优先 merge 而非新建**：后续反馈更新既有技能而非产生重复。
  - **离线提取**：可直接导入历史对话/轨迹，不需要重放交互。
  - **SkillEvo 1.0**：replay → evaluation → mutation → promotion 四步迭代自进化。
- 对我们的意义：**这是「不碰权重也能自进化」的最经济实现，是 MVP 的第一优先级可抄对象。** 它把「自进化」降级为文件版本管理问题，风险与算力成本都极低。

### 3.4 学术与公共基础设施（不需要自研，可直接对接）

**Prime Intellect**（<https://github.com/orgs/PrimeIntellect-ai/repositories>）
- **OpenDiLoCo**：Hivemind 之上的可复现 DiLoCo 实现，全球分布式低通信训练。
- **INTELLECT-1 / INTELLECT-2 / INTELLECT-3**：INTELLECT-2 号称首个在**异构、无需许可**算力网络上完成的 32B 全异步 RL 训练（[报道](https://www.163.com/dy/article/JVI93KEF05119734.html)）；INTELLECT-3 为 **106B MoE**，仅用 **512 张 H200** 完成分布式 RL 并全开源（[报道](https://eu.36kr.com/de/p/3589329201954820)）。
- **prime-rl**：专为大规模**异步**去中心化 RL 设计的训练引擎；配套 **Environments Hub**（开放 RL 环境中心）与 **SYNTHETIC-1/2** 合成数据引擎。
- **TOPLOC**：可验证推理方法（验证 LLM 提供方确实使用了正确模型配置），MIT，Python（<https://github.com/PrimeIntellect-ai/toploc>）。

**Nous Research — Psyche / DisTrO / DeMo**（一手架构文档：<https://nousresearch.com/nous-psyche>）
这是**目前公开得最完整**的去中心化训练架构，几个可复用的硬数字与设计：
- **通信压缩原理（DeMo → DisTrO）**：类比 JPEG——把动量张量经 **DCT** 变换到频域，只传**能量最高的 top-k 分量**（值 + 索引），同步时 IDCT 恢复近似梯度。关键修正：不像 JPEG 那样固定压缩高频，而是取**幅度最大**的分量（不论频率位置），避免系统性偏置。DCT 基矩阵可预生成分块，**变换开销 < 总训练时间的 1%**。
- **1-bit 量化**：实测**只传 DCT 的符号（±1）就能还原出正确动量矩阵**，幅度几乎无额外信息 → 压缩 **3 倍以上**（`quantize_1bit` 开关）。
- **Overlapped DisTrO**：不等上一步下载完就开始下一步训练；因 DisTrO 结果大小随参数量**亚线性**增长，理论上通信延迟**不再成为瓶颈**。
- **三段式架构**：Coordinator（状态在 **Solana 智能合约**上：运行元数据、参与者、状态迁移、随机性、同步点）+ Clients（GPU 节点，担任 training / witnessing / verifying 三职）+ Data Provider（本地或 HTTP/TCP）。
- **Epoch 生命周期**：Waiting（等最少成员）→ Warmup（下载模型，掉线回退）→ Training → Witness（见证者产出经 **Bloom filter** 压缩的 witness proof）→ Continuation/Cooldown → Checkpoint（部分节点上传 HF，或 **P2P 分片拉取** checkpoint）。
- **网络层用 Iroh**：Nous 原文称 UDP 打洞成功率 **~90%**，对比 **libp2p ~70%**、**BitTorrent 通用 UDP 打洞 60–70%**；回退中继；支持 QUIC 连接迁移（换网/换 IP 不断连）；节点身份是 **32 字节 Ed25519 公钥（NodeId）**，默认端到端加密与认证；用 `iroh-gossip`（HyParView + PlumTree）广播元数据，`iroh-blobs` 传结果。

  > ⚠️ **数据冲突（重要，已交叉核对）**：上表的 90% 是 **Nous 作为 Iroh 使用方的自述**。而第三方超大规模实测（DCUtR，**440 万次打洞尝试 / 8.5 万个网络 / 167 个国家**）给出的是 **70% ± 7.1%**（首次尝试成功率 97.6%）——见 <https://ar5iv.labs.arxiv.org/html/2510.27500>（ACM IMC 2026：<https://dl.acm.org/doi/10.1145/3777912.3809138>）。Tailscale 官方则称其直连成功率「远高于 90%」（<https://tailscale.com/blog/nat-traversal-improvements-pt-1>）。
  > **结论：不要按 90% 做容量规划。真实互联网上应假设约 30% 的连接必须走中继**，并据此设计**可自托管的中继池**（详见文档 03）。
- **容错**：客户端对失联节点发 health check 给 coordinator，足够多的负面健康报告则剔除该节点并**重训其份额**。
- **验证（作者坦言是 open problem）**：位级校验不可行（浮点非确定性 + DisTrO 本身引入可变性）。当前做法是**重算比对**，用三个互补指标判定「诚实节点正常波动区间」：**Jaccard 指数**（重叠度，但可被乱序绕过）、**Manhattan 几何**（总量差，但可被抵消绕过）、**Hamming 距离**（逐位差，但配合使用才稳健）。明确承认「太严则误报、太松则被持续微幅投毒」需要实证研究。
- **Consilience 40B**：首个 Psyche 实跑目标——40B 参数、**20T tokens**、**MLA 架构（dense 而非 MoE）**，数据 = FineWeb 14T + FineWeb-2 4T + The Stack V2（0.2T 上采样到 1T）；刻意**不做 annealing**并同时发布 annealed 版本。

**其他验证路线**：Gensyn 的 **PoL**（Proof of Learning）、Grail 的密码学验证（见 [IOSG 研报](https://www.techflowpost.com/en-US/article/29654)）。

### 3.5 关键算法演进链（补：这条线的收敛性在持续改善）

`DeMo（解耦动量 + DCT 压缩）` → `DisTrO（同类优化器族）` → **`SparseLoCo`**：把本地动量与 **error feedback** 联系起来，在**显著降低通信量**的同时**性能超过 DiLoCo 与 DeMo**，位于「loss vs 通信量」的 Pareto 前沿（[arXiv:2508.15706](https://browse-export.arxiv.org/pdf/2508.15706)，[OptML 2025](https://opt-ml.org/papers/2025/paper118.pdf)）。另外 **NoLoCo**（无外层优化的 DiLoCo 变体）也在此谱系中。

> 含义：底层算法在快速进步，**自研通信压缩的性价比很低**——应该把「用哪个优化器」做成**可插拔**，等社区收敛。

## 四、空位分析：没人做好的三件事

逐条对比后，下面三件事在现有项目里**要么没人做、要么做得不认真**：

### 空位 1：「可验证的进步」——缺一把通用的尺子
- Continuum 自己承认「累积经验能否带来长周期能力提升」是未知；Psyche 承认验证是 open problem；DGM 类工作只在 SWE-bench 上证明，且**不能证明跨领域迁移**。
- 现状：大家都在**声称**会变强，但几乎没人提供**「本周比上周强了多少、强在哪」的持续可审计账本**。
- 机会：把「进化」变成**可测量的 KPI 曲线**（本地任务集上的通过率、复习正确率、时延、代价），并且**每次采纳一个 gene/skill 都必须留下前后对比证据**（Continuum 的 adopt/reject 已给出正确形态，但没提供通用度量层）。

### 空位 2：「个人算力现实」——论文假设与家用设备之间的鸿沟
- 去中心化训练论文的现实前提是「有闲置 GPU 集群、有稳定上行带宽」；而个人场景是**一台笔记本 + 一部手机 + 家用 NAT + 会休眠**。
- 现状：Continuum 在单机上做了极认真的资源治理（KV-slot 经济、内存压力否决），但它的 Grid 仍是「你自己拥有的多台机器」，**没有解决不可靠、会休眠、带宽差的开放式参与**。
- 机会：把「**节点随时可离线**」当作第一公民来设计——这对个人场景是常态而非异常。Psyche 的 epoch/cooldown/见证机制是一个可借鉴的答案骨架。

### 空位 3：「双向学习」——人的学习与 AI 的学习没有真正打通
- 现有项目几乎都只做一半：Continuum/AutoSkill 只做「AI 自己的学习」；Anki/FSRS/DKT 生态只做「人的学习」；两者之间最多共享一个「知识库」。
- 现状：**没有项目把「人复习某个知识点」与「AI 更新某个技能/权重」放进同一个反馈回路**。
- 机会：这是本项目最有想象力的差异点——**Human-in-the-loop 不只是给 AI 打分，而是人的学习行为本身就是 AI 的训练信号**（例如：人反复在某个知识点出错 → 该知识点对应的 AI 技能被标记为薄弱 → 触发技能 review/重训；反之 AI 生成的讲解被人跳过 → 该生成策略降权）。这也天然解决了「个人数据从哪来」的冷启动问题。

## 五、立项建议

### 5.1 差异化定位一句话
> **不是「训练一个更大的模型」，而是「一个会记账的自进化学习系统」：把每一次人的学习与 AI 的工作都变成带证据的经验，跨设备同步经验与轻量适配，并以可审计的曲线证明它真的在变强。**

### 5.2 建议的 MVP 路径（按风险从低到高，每步都可独立演示）

| 阶段 | 目标 | 技术选型建议 | 可验证产物 |
|---|---|---|---|
| **P0 记忆层** | 经验可沉淀、可检索、可人工编辑 | 抄 **ReMe** 的「记忆即文件」分层（session → daily → digest，Markdown 落盘）+ BM25/wikilink 兜底 | 一份可 git diff 的记忆库 |
| **P1 技能层（自进化 v0）** | 从经验中提取/合并可复用技能，带版本 | 抄 **AutoSkill**：`SKILL.md` + 空提取保护（无持久约束则不建模）+ merge 优先 + SkillEvo 的 replay/eval/mutation/promotion | 技能库版本历史 + 使用命中率 |
| **P2 闭环与度量（**差异化核心**）** | 采纳必须有证据：前后对比、可审计账本 | 借 **Continuum 的 adopt/reject + Forge-Alloy 契约**（record → hash → eval → 证据）；对齐 2508.07407 四要素框架 | 「本周 vs 上周」能力曲线 + 每次采纳的证据包 |
| **P3 跨设备分发** | 经验/技能/适配器在设备间流动 | **Iroh**（QUIC 迁移、NodeId 身份、自带 relay 回退）优先于 libp2p；⚠️ **按打洞成功率 ~70% 做容量规划（约 30% 走中继）**——见 §3.4 的数据冲突说明，需自托管中继池；记忆用 CRDT 或「文件 + git」做同步；移动端只做客户端与轻任务 | 两台设备互相同步并可离线合并 |
| **P4 权重层（谨慎）** | LoRA 级适配器作为「gene」继承 | **先只做 LoRA 训练 + 评估 + 分发**，不要碰全参数分布式训练；基座用 llama.cpp/GGUF 量化模型；参考 Continuum 的 gene/genome/lineage | 一个被采纳的 LoRA gene + 前后基准对比 |
| **P5 分布式训练（观望）** | 多机协同训练 | **默认不做**（判据见文档 01 §⑦「第 0 条」）。若要做，优先 **SparseLoCo**（error feedback + 1–3% top-k + 2-bit，**超过全精度 DiLoCo**，复杂度远低于 DCT），DCT/1-bit 作为最后一公里优化；**绝不把 all-reduce 放上广域网** | — |

### 5.3 明确「不做」清单（防止项目膨胀致死）
1. **不自研 P2P / NAT 打洞** → 用 Iroh。
2. **不自研通信压缩优化器** → 用 SparseLoCo/DisTrO，且留给未来替换。
3. **不从零训练基座模型** → 用现成量化模型 + LoRA。
4. **不做区块链/代币激励**（除非目标就是 Web3）→ 个人/小团队场景用信誉与本地信任即可。
5. **不追求 3D 社交空间/化身**（Continuum 的重投入方向）→ 与「学习系统」核心价值无关。

### 5.4 风险登记（按杀伤力排序）
| 风险 | 说明 | 缓解 |
|---|---|---|
| **自我进化的效果无法证明** | 这是全行业未解问题（Continuum 亲自承认）；若 P2 度量做不出来，项目就只剩「记忆库」 | P2 提前做、且允许「负结果」被如实记录；用确定性 grader 而非 LLM 自评 |
| **reward hacking / 规格博弈** | 任何自评回路都会被钻空子 | 硬性 grader + 人工确认关口 + 采纳需留证据 |
| **AGPL 传染** | Continuum 是 AGPL-3.0 | 只读架构思路，不复制代码 |
| **移动端常驻不可行** | Android/iOS 后台会杀进程、限制网络 | 移动端定位为「客户端 + 感知端」，重活放桌面/常驻机 |
| **冷启动无数据** | 自进化需要经验量 | 见空位 3：把人的学习行为作为第一份数据源 |
| **家用网络上行带宽** | 同步与训练都吃上行 | 只同步适配器/技能/记忆增量，基线模型各端各自下载 |
