# 06 · 度量与验证：如何证明系统「真的在变强」

> 调研时间：2026-10-26 ｜ 定位：**本项目的差异化核心**（见文档 05 的空位 1）
> 一句话：全行业都在声称自进化，但几乎没人提供「本周比上周强了多少、强在哪、代价多少」的持续可审计账本。**先解决度量，再谈进化。**

---

## 一、为什么度量必须排在第一位

三个独立证据说明「有效性无法证明」是这个赛道的共性硬伤：

1. **Continuum 自己承认**：其三大科研问题之一是「累积的真实经验能否带来长周期能力提升」，作者明确把这些列在 "Still unknown" 而非 "Measured"（<https://github.com/CambrianTech/continuum>）。
2. **Psyche 作者明确写**：「我们已经发展出验证的理论模型，但**实用实现仍是开放问题**」（<https://nousresearch.com/nous-psyche>）。
3. **实证反例**：一项 2026 年 Meta 的研究发现，自我改进策略会**收敛到能骗过裁判、却不可检测的对抗性答案**（转引自 <https://github.com/robmclarty/fascicle/blob/6429191fdb7031100866a4e18b08f5b009746987/examples/amplify/research/05-pitfalls.md>，该来源为二手整理，**原始论文待核实**）。

> ⚠️ 若度量做不出来，本项目退化为「一个带记忆的笔记软件」——那也仍然有用，但必须**诚实地承认这一点**，而不是宣称自进化。

---

## 二、三层度量体系（对应系统的三个层面）

| 层 | 测什么 | 可用基准/指标 | 成熟度 |
|---|---|---|---|
| **L1 记忆/检索层** | 存进去的东西能不能被正确取出来 | LoCoMo、LongMemEval、MEME、MemoryAgentBench | ✅ 有公开基准 |
| **L2 持续学习层** | 学了新的，旧的会不会忘；有没有正迁移 | ACC、**F（遗忘）**、FT（前向迁移）、BWT（后向迁移）、AULC、TUE、CL-Score | ✅ 指标已标准化 |
| **L3 人的学习层** | 用户是否真的学会了（而非「感觉学会了」） | FSRS 保留率、前测/后测、**延迟测试**、迁移测试 | ✅ 学习科学成熟（详见文档 04） |

**关键设计原则**：三层必须用**同一套时间轴**记账。任一时刻 t，都能回答：
「此刻 L1 检索命中率 = ?，L2 遗忘率 = ?，L3 用户保留率 = ?，以及本次采纳了哪个技能/gene、代价是多少」。

## 三、L2 核心：一套可直接照抄的持续学习指标

来源：**SWE-Bench-CL**（Joshi, Chowdhury, Uysal，Columbia University，arXiv:2507.00014，<https://github.com/thomasjoshi/agents-never-forget/>）——把 SWE-Bench Verified 按**时间顺序 + 难度课程**重排成 8 个仓库序列、共 273 个任务，专门测「累积经验 / 跨任务迁移 / 抗灾难性遗忘」。

### 3.1 记号
- `N` = 总任务数；`a_{i,j}` = 学完任务 i 之后在任务 j 上的成功率（**每次学新任务后，回测所有旧任务**，得到性能矩阵）；`ā_{0,j}` = 任务 j 的零样本成功率。

### 3.2 指标表（可直接实现）

| 指标 | 公式 | 含义 |
|---|---|---|
| **SR** | `a_{i,j} = p_j^pass / p_j^total` | 单任务成功率 |
| **ACC** | `(1/N) Σ_{j=1..N} a_{N,j}` | 学完全部任务后的平均准确率 |
| **F（遗忘）** | `(1/(N-1)) Σ_{j=1..N-1} ( max_{1≤k≤j} a_{k,j} − a_{N,j} )` | **平均遗忘**：早期任务上的性能衰减。这是「自进化」最该盯住的负向指标 |
| **FT（前向迁移）** | `(1/(N-1)) Σ_{i=1..N-1} ( a_{i,i+1} − ā_{0,i+1} )` | 先前任务对新任务的帮助（相对零样本） |
| **BWT（后向迁移）** | `(1/(N-1)) Σ_{i=1..N-1} ( a_{N,i} − a_{i,i} )` | 学新任务对旧任务的影响（负值 = 遗忘） |
| **AULC** | `(1/N) Σ_{i=1..N} ( (1/i) Σ_{k=1..i} a_{k,k} )` | **学习曲线下面积**——比最终分数更能反映「学得快不快」 |
| **TUE（工具效率）** | `median(time\|success) / median(time\|all)` | 工具使用效率（成功运行 vs 全部运行的中位耗时之比） |
| **CL-Score** | `ACC − λ·F + …`（可调权重 λ） | 把稳定性/可塑性折成单一分数 |
| **CL-Fβ** | 综合稳定性-可塑性权衡的复合分 | 作者提出的复合指标 |

> **落地建议**：本项目的核心 KPI 建议定为 **`AULC`（学得多快）+ `F`（忘得多不多）+ 单次采纳的净收益**，而不是任何单一的「通过率」。因为「通过率」可以被 reward hacking 刷，而 `F` 与 `AULC` 会同时暴露「变强」和「退化」。

### 3.3 另可参考
- **Continual Learning Bench 1.0**（Snorkel AI，<https://snorkel.ai/blog/continual-learning-ai-agents-explained/>）：强调持续学习的三个要素是**任务序列（数据层）、记忆信号、反馈回路**，并指出下一步需要「更多系统、更多专家设计的任务域、以及更深的误差分析——弄清智能体在哪里学到、在哪里遗忘、在哪里带走了错误的教训」。
- 编码智能体方向已有公开代码与数据：<https://github.com/thomasjoshi/agents-never-forget/>

## 四、三条必须知道的反向证据（会直接改变架构决策）

### 反例 1：复杂智能体记忆可能不如朴素 RAG ⚠️（最新，2026-10-22）

**《Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought》**（Bao, Zhang, Zhang, Lou, Wen, Luo，arXiv:2610.30755，<https://arxiv.org/abs/2610.30755>，62 页，CC-BY-4.0）

- 构造 **Raw-RAG** 基线：不做 mutation、不做结构化组织、不做学习式检索，只做**对原始历史的稠密检索 + 重排序**，把证据喂给 reader LLM。
- 在 **LoCoMo、LongMemEval、MEME、MemoryAgentBench** 四个基准上，Raw-RAG 在 **7 个「基准×模型」设置中的 6 个排第一**，比最强的对照智能体记忆系统**高 0.13–5.53 分**。
- 原因分析：Raw-RAG 对**必要证据的覆盖率更高**，足以抵消其**利用率较低**的劣势。有用证据不止是「答案值」，还包括**推导答案所需的关系与依赖路径**；即使给转换后记忆库**完全访问权**，相比原始证据仍有精度差距——**保留原始信息本身有价值**。
- 结论：作者明确表示这些发现**挑战了在所述对话任务上使用复杂智能体记忆的必要性**，并把朴素 RAG 立为**必备基线（essential baseline）**。

**对架构的硬性含义**：
1. **P0 记忆层先做 Raw-RAG 基线**，别一上来就 GraphRAG / 多级 rollup / 自学习检索。所有复杂方案必须**证明能打败这个基线**才允许上。
2. **原始历史必须永久保留**，转换/摘要只作为**附加索引**，不能替代原文（这恰好与 ReMe 的「记忆即文件」、Continuum 的「不把无限 transcript 叫一生」形成互补——但结论是：**别删原文**）。
3. 报告分数时必须**同时给出覆盖率与利用率**，否则无法解释为什么变好/变差。

### 反例 2：检索到不相关内容会显著污染输出 ⚠️

同源 SWE-Bench-CL 论文的 **prompt poisoning** 实验：给目标任务 B 的提示**前置一个与 B 毫不相关的任务 A 的 issue-patch**，测量生成解的语义漂移 `1 − cos(clean, poisoned)`：

- 即使是**结构上完全不相似、且来自更简单任务**的上下文，也**稳定诱导出平均 ≈0.45 的高语义漂移**（论文标注的「高漂移」阈值为 0.3）。
- 含义：**记忆增强的智能体存在结构性脆弱**——「朴素地检索并拼进上下文会降低性能」，除非检索足够有辨别力、或智能体具备**门控无关信息**的能力。
- 论文因此强调：要评估智能体**如何使用**记忆，而不只是**是否有**记忆。

**对架构的硬性含义**：
- 记忆注入必须带**门控（gating）+ 相关性阈值 + 可归因**，并在账本里记录「本次任务注入了哪几条记忆、它们是否被引用、是否导致漂移」。
- 「检索命中率」不是好指标——**检索的净贡献**才是。

### 反例 3：本地小模型在真实软件任务上几乎不可用 ⚠️

同一论文的实证部分：用 CodeLlama-13B、Gemma-3-12B、Mistral-7B（经 **Ollama**）以及 Gemini-2.0-Flash 在 SWE-Bench-CL 上跑：

- **整体通过率持续低于 8.5%，且常常显著更低**；记忆启用条件下**通常与基线持平或略差**。
- 作者给出的解释很关键：由于评测框架不兼容导致高失败率，**「记忆」里塞满的主要是先前失败尝试的信息**，形成 **garbage-in, garbage-out**。

**对架构的硬性含义**：
1. **本地 7B–13B 级模型不足以自主修复真实仓库**——不要把「本地模型自动改代码」当作 MVP 的核心能力。
2. **失败经验入库必须带质量分级**：失败记录不能与成功记录同等对待，否则记忆库会被噪声淹没（这条直接决定「经验→技能」管道的准入规则）。
3. 评测框架本身要能**透明报错**，否则评测失败会被误读为能力不足。

## 五、自进化的五种已知失败模式（必建监控）

来自 2026 年的一份工程综述整理（<https://github.com/Corneldj/context-engineering/pull/5/files>，二手整理，原始出处待核实），列出自我改进系统**特有的**失败模式：

| 失败模式 | 表现 | 监控手段 |
|---|---|---|
| **Reward hacking** | 指标上升但底层性质未改善 | 硬性 grader + 留出集 + 人工抽检 |
| **Diversity collapse** | 演化多样性坍缩到单一策略 | 归档多样性度量（MAP-Elites 网格覆盖率） |
| **Catastrophic forgetting** | 学新忘旧 | 指标 **F**（见 §3） |
| **Silent drift** | 目标悄悄漂移，没有报错 | 目标/规格的版本化 + 漂移检测 |
| **Over-optimism** | 自评分数虚高 | **禁止用 LLM 自评作为唯一判据** |

该文给出的原则值得直接抄进设计文档：

> **「meta-agents propose; humans and held-out evaluations dispose.」**
> （元智能体提出方案；由**人类**与**留出集评测**裁决。）
>
> 以及：**「Track per-category scores; the mean hides churn.」**
> （必须**按类别**记录分数——**均值会掩盖剧烈的来回震荡**。）

## 六、采纳协议（Adopt / Reject）：把「进化」变成可审计事件

借 Continuum 的 `adopt / reject` 形态 + Forge-Alloy 的「配方即收据」思想 + 上面的指标，给出可直接实现的最小协议：

```text
function consider_candidate(cand):        # cand = 新技能 / 新 prompt / 新 LoRA
    # 1) 冻结评估集：当前任务序列的快照 + 留出集（held-out）
    # 2) 候选上线前必须先在沙箱内跑，不触达真实任务
    before = eval(golden_set ∪ heldout)          # 得到 ACC_before, F_before, AULC_before
    apply_candidate(cand, sandbox=True)
    after  = eval(golden_set ∪ heldout)          # 得到 ACC_after,  F_after,  AULC_after

    # 3) 三重门槛，缺一不可
    gain    = after.ACC - before.ACC             # 净收益
    forget  = after.F   - before.F                # 未加重遗忘
    cost    = measure_time_tokens(cand)           # 代价（时间/算力/token）

    verdict =
        REJECT  if gain <= 0                       # 无净收益
        REJECT  if forget > FORGET_BUDGET          # 以遗忘换取收益 = 不接受
        REJECT  if gain / cost < EFFICIENCY_FLOOR  # 性价比过低
        REJECT  if not human_approved(cand)        # 人类关口（可配置）
        else ADOPT

    # 4) 无论采纳与否，都写入不可变更的证据账本
    ledger.append({
        candidate_id, parent_id,                 # 血统
        evidence: { before, after, per_category },# 分类别分数，不只给均值
        artifacts: { hashes, config, seed, hardware, duration },
        verdict, decided_by, decided_at,
    })
    return verdict
```

**账本的四个硬要求**：
1. **只追加、不可改写**（append-only），可 git 追溯；
2. **记录血统（lineage）**：这个技能/gene 从哪来、基于谁、影响了谁；
3. **记录代价**：不记代价的「变强」等于没有约束的膨胀；
4. **按类别记录**，且允许**负结果被如实记录**——「本周无进步」是一条合法且有价值的记录。

## 七、度量层的最小可运行实现（P2 建议）

在家用设备上可跑（参考实测：Qwen3.8-27B 约 3.5-bit / 12.2 GB，RX 9070 XT 上约 **50 tok/s**；gemma-4-26B-A4B / 13.3 GB 约 **85 tok/s**——来源 <https://pypi.org/project/make-localllm-easier/>，厂商自述，**待独立核实**）：

| 组件 | 选型 | 说明 |
|---|---|---|
| **任务序列集** | 自建小型序列（10–30 个任务 × 3–5 个序列） | 参照 SWE-Bench-CL 的「时间顺序 + 难度课程」构造法；必须**每个任务有确定性 grader** |
| **Grader** | **确定性**（单元测试 / 精确匹配 / 可执行结果）优先 | 绝不用 LLM 自评做唯一判据 |
| **留出集** | 与训练/演化集**物理隔离**，且不参与任何自动优化 | 防 reward hacking 的唯一可靠手段 |
| **记账** | 追加式 JSONL / SQLite + 文件 hash | 后期可直接转成图表与审计报告 |
| **指标的界面** | `AULC` 曲线 + `F` 柱状 + per-category 热力图 | 「均值掩盖 churn」，必须分类展示 |
| **沙箱** | 容器或受限子进程 | 候选在生效前不得触达真实数据与真实任务 |

## 八、反模式清单（明确禁止）

1. ❌ **用 LLM 自评作为唯一进步判据** —— 必被 reward hacking。
2. ❌ **只看均值** —— 会掩盖类别间的剧烈震荡。
3. ❌ **只报最终分数，不报遗忘与代价** —— 掩盖了「用遗忘换分」和「用算力堆分」。
4. ❌ **在测试集上做演化** —— 等于自己给自己出题。
5. ❌ **把失败经验当成功经验同等入库** —— garbage-in, garbage-out（反例 3）。
6. ❌ **默认复杂记忆/GraphRAG 更优** —— 必须先打败 Raw-RAG 基线（反例 1）。
7. ❌ **只测一次** —— 单次结果无法区分重构与噪声。
