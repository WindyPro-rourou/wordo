# 13 · 知识树与知识图谱的自动生成

> **调研日期**：2026-10-27
> **可信度标注**：`✅ 一手` = 论文原文 / 官方文档 / 官方仓库；`⚠️ 二手` = 博客、公众号、技术社区文章、二手综述；`❓ 待核实` = 未找到可引用的原始来源。
> **定位**：本文回答「知识树**怎么造出来、长什么样、怎么落地**」。算法原理（BKT / DKT / IRT / FSRS / 先修 DAG 的公式与推断细节）见 `docs/资料/04-学习科学与知识表征.md`，本文不重复推导，只写**接口与数据结构**。
> **与本项目的关系**：知识树是多端教学/测试系统（Windows + Android + iOS/iPadOS + ESP32 单词机）的骨架——它决定测评怎么出题、讲解按什么顺序、用户「哪里不会」如何定位、复习如何排程。

## ① 一句话结论

**结论**：不要试图一次造出「完美知识图谱」——正确做法是**两级分离**：用 LLM 从教材目录/正文**批量抽候选 KC + 先修边**（召回优先、低成本、允许脏），再用**「题目标注一致性 + 专家抽检 + 考纲对照」三闸门**把候选收敛成可上线的**稳定 ID 知识树**；树的存储必须**分层裁剪**（主干树 + 叶子 KC 分片下发），因为 ESP32 单词机这类弱端只能吃下几百个 KC 的扁平列表，吃不下全图。

## ② 知识树数据模型

### 2.1 层级结构设计

**核心判断：区分「目录树」与「知识 DAG」——这是两种不同的东西，必须分表存。**

- **目录树（Curriculum Tree）**：`学科 → 教材/版本 → 册/年级 → 章节 → 小节`。它是**人为切分的容器**，一棵严格的树（一个节点只有一个父），主要用途是**导航、找资料、按章节出题、定位「书上第几页」**。它会随教材改版而变。
- **知识 DAG（Knowledge Graph）**：`KC → 子 KC`（可选的 has-part 树） + `先修边 prerequisite` + `关联边 related/synonym`。它是**认知结构的建模**，是一个**有向无环图**，主要用途是**诊断、根因定位、排程、讲解顺序**。它应当尽量**跨教材版本稳定**。

**为什么要分离**：教材改版会重排章节（第 3 章和第 4 章互换），但「分数加法需要先会通分」这个认知事实不变。如果先修边挂在章节节点上，改版一次全图崩。所以：

```
章节 --(contains, 弱约束，可改)--> KC
KC   --(prerequisite, 强约束，尽量不改)--> KC
```

**落地建议的中间层**：在 KC 之上引入 **「知识点簇 / 单元（Unit）」** 这一聚合层，作为「一棵子树对应一个小节 / 一次教学闭环」的单位。它同时是**出题单元**和**排程单元**，避免直接拿 2000 个叶子 KC 去做 UI 和排程。

推荐层级（本项目，7 层，其中 4–6 层是知识层）：

| 层 | 名称 | 数量级（单学科） | 稳定性 | 用途 |
|---|---|---|---|---|
| L0 | 学科 Subject | 1 | 极稳 | 入口 |
| L1 | 教材/课程体系 Textbook | 1–3 | 稳 | 版本隔离 |
| L2 | 册 / 年级 Volume | 2–12 | 中 | 进度、学期 |
| L3 | 章 Chapter | 10–40 | 中（改版会动） | 导航、章节测评 |
| L4 | 节 / 单元 Section(Unit) | 40–200 | 较稳 | **教学闭环、单元测评、排程单元** |
| L5 | 知识点 KC | 200–3000 | 稳（要保 ID） | **诊断原子、BKT/DKT 的 KC 标签** |
| L6 | 子知识点 Sub-KC / 技能点 | 可选 | 稳 | 细粒度技能（如「通分」下的「找最小公倍数」） |

**边的两类（外加两类有用的扩展）**：

1. **prerequisite（先修）**：`A --prereq--> B` 读作"要学 B 必须先掌握 A"。带**强度**（hard/soft）与**权重**。hard 边用于根因定位的硬阻断，soft 边用于排序加权。
2. **related / synonym（关联/同义）**：横向关系。`related` = 相关（如"一元一次方程" ↔ "天平模型"），用于**推荐类比、跨章节串联**；`synonym` = 同一知识的不同叫法（"勾股定理" = "毕达哥拉斯定理"），用于**抽取去重与合并**。
3. **扩展边（强烈建议加）**：
   - `assesses`：题目 → KC（题与 KC 的映射），是诊断的入口，也是**校验先修边**的数据来源。
   - `confusable / misconception`：A ↔ B 易混淆（"周长 vs 面积"），用于**干扰项生成与错因分类**。

**关键的建模纪律**：先修边一定要**允许自环外的冗余（transitive reduction 只在渲染时做，不在存储时做）**。也就是说，如果 A→B→C 且 A→C 也成立，**存 A→C 是好事**：因为 BKT/根因定位要算「直接先修」，冗余边会在后面被"最短路径化"处理，而删掉就再也恢复不了。

### 2.2 知识点粒度问题

**行业共识（先验，后文核实）**：

- **ALEKS**（McGraw-Hill 的 K-12/大学自适应数学系统）：采用**"知识点 = 一个可被单独评估的、最小可教学单元"**的粒度，其内部称为 "item type / topic"，典型一门课 **约 200–500 个 topic**。它是"能出 3–5 道题独立判断会不会"的下界。
- **Khan Academy**：其知识地图（Knowledge Map）以 **"skill"** 为单位，一节 skill 通常对应 **1 个视频 + 1 组练习**，粒度大致等同于"课时内的一个技能"；其 `prerequisite` 边是**人工维护 + 内容团队校订**（这是它知识地图可靠的原因，也是成本瓶颈）。
- **K-12 学科知识图谱类项目（中文）**：粒度多数落在 **教材小节的 1/2 ~ 1/4**，即一个小节拆成 2–5 个 KC。

**粒度判据（本项目可直接用，A/B/C 三选一即可上）**：

一个"合格的 KC"必须同时满足：

- **(A) 可测性**：能针对它**独立**写出 ≥ 3 道题（不依赖同层其他 KC 的题面提示）。
- **(B) 可教性**：能用**一段 1–3 分钟的讲解 / 一页卡片**把它讲完，不需要现场引入两个新概念。
- **(C) 可诊断性**：两个学生在这个 KC 上的掌握度应当**能分化**（如果全对或全错，说明它不是一个 KC，而是"太简单"或"前置缺失"）。

**太粗的症状**：诊断只能给出"整章不会"，无法定位；复习排程只能整章重来，效率崩。
**太细的症状**：① 一个 KC 出不出 3 道题 → 题库爆炸；② KC 数 × 题目数 = 标注成本爆炸；③ 知识点之间高度冗余，掌握度曲线几乎完全相关（做 BKT 时参数不可辨识）。

**经验数字（供本项目预算用）**：

| 学段/学科 | 单册 KC 数（推荐） | 单学科全学段 KC 总数 |
|---|---|---|
| 小学英语（单词机主战场） | 60–150 / 册 | 800–2000 |
| 小学数学 | 40–80 / 册 | 500–900 |
| 初中数学 | 50–120 / 册 | 500–1000 |
| 高中物理 | 80–150 / 册 | 600–1200 |

**粒度是"可调参数"，不是一次性决策**：建议第一版**故意偏粗**（一个小节 1–3 个 KC），因为粗粒度**可以后验拆分**（原 KC 的答题记录可以按新子 KC 的题目归属重新分配），而细粒度**无法后验合并**（合并后才知道哪些题对应合并后的 KC，历史记录归属会糊）。**单调细化原则**：只拆不合。

### 2.3 知识点属性 schema

**设计原则**：`稳定字段`（ID/名称/认知层次）+ `生成字段`（总数可重算的，如难度）+ `运行时字段`（每用户掌握度）**三者分离**。运行时字段**绝不能写回知识树本体**（否则一人一份树，跨端同步炸掉）。

字段清单（字段名即最终 schema 用名）：

| 字段 | 类型 | 说明 | 稳定性 |
|---|---|---|---|
| `kc_id` | string | **永不变的稳定 ID**，见 §6 ID 稳定性 | 永久 |
| `name` | string | 主名称（中文） | 可改 |
| `aliases` | string[] | 别名/同义（"勾股定理"/"毕达哥拉斯定理"） | 可增 |
| `name_en` | string? | 英文名（双语学科、查重） | 可改 |
| `parent_kc_id` | string? | has-part 父 KC（子知识点） | 可改 |
| `section_id` | string | 所属小节（容器归属，可改） | 可改 |
| `subject_id` / `volume_id` | string | 冗余存储，方便裁剪下发 | 固定 |
| `kc_type` | enum | `concept`(概念) / `skill`(技能/程序) / `fact`(事实/记忆) / `principle`(原理) / `method`(方法) | 较稳 |
| `bloom` | enum | `remember` / `understand` / `apply` / `analyze` / `evaluate` / `create` | 较稳 |
| `difficulty` | float 0–1 或 a/b | 难度（IRT 的 b 或归一化） | 可重算 |
| `discrimination` | float? | 区分度（IRT 的 a），需答题数据后回填 | 可重算 |
| `item_types` | string[] | 适配题型：`single_choice`/`fill_blank`/`spelling`/`calculation`/`proof`/`reading`/`listening` | 可改 |
| `assessable` | bool | 是否可测（有些 KC 是组织性概念，不出题） | 较稳 |
| `examples` | object[] | 代表例题（题 ID 引用 + 题干快照） | 可改 |
| `est_learn_minutes` | int | 预计学习时长（排程用） | 可估 |
| `keywords` | string[] | 检索关键词（LLM 抽取产物，用于对齐题目） | 可改 |
| `source` | object | 抽取来源：教材页/目录路径/LLM 模型名/抽取时间 | 永久留痕 |
| `confidence` | float | 抽取置信度（0–1），低于阈值进人工队列 | 永久 |
| `review_status` | enum | `auto` / `llm_verified` / `human_checked` / `expert_signed` | 可升级 |
| `active` | bool | 软删除（弃用但不删，保 ID） | 可改 |
| `superseded_by` | string? | 被哪个 KC 取代（拆分/合并时用） | 永久 |
| `schema_version` | int | 该行遵循的 schema 版本 | 永久 |

**先修边属性**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `from_kc` / `to_kc` | string | A → B（学 B 前需 A） |
| `strength` | enum | `hard` / `soft` |
| `weight` | float 0–1 | 边权（排序与根因打分用） |
| `evidence` | enum | `textbook_order` / `llm_semantic` / `data_mined` / `expert` |
| `confidence` | float | 置信度 |
| `notes` | string? | 说明（为什么这条边成立） |

**掌握度（运行时，独立表，不进知识树）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` / `device_id` | string | 用户（离线优先时以 user_id 为准，device 合并） |
| `kc_id` | string | KC |
| `mastery` | float 0–1 | 当前掌握度（BKT 后验 / DKT 输出 / Elo/IRT 映射） |
| `model` | string | 该值由哪个模型产生（`bkt` / `dkt` / `elo`） |
| `attempts` / `correct` | int | 计数 |
| `last_seen_at` | ts | 最近作答时间 |
| `stability` / `difficulty_fsrs` | float | 若用 FSRS 做 KC 级排程，需要 KC 级记忆参数（见 §C13） |
| `due_at` | ts | 下次复习时间 |
| `origin_device` | string | 哪台设备产生的（用于冲突合并） |

### 2.4 与知识追踪的对接

**KC 就是知识追踪里的 KC 标签**。BKT/DKT 的输入输出与知识树的关系：

```
知识树(L5 KC)  --kc_id-->  题目的 assesses 边  --(题, 对/错)-->  知识追踪模型
                                                                    |
                                                              per-KC mastery
                                                                    |
                          ┌─────────────────┬──────────────────┬────┘
                          ▼                 ▼                  ▼
                     出题（选题策略）    诊断（根因定位）    排程（FSRS/ZPD）
```

- **BKT**：每个 KC **独立一套** `(P(L0), P(T), P(G), P(S))`（公式见 04 文档）。**这意味着 KC 数量直接决定参数数量**：3000 个 KC × 4 参数 = 12000 个参数，冷启动时全靠先验，数据稀疏。→ **这是"粒度不能太细"的第二个硬理由**（第一个是标注成本）。
- **DKT**：输入是 `(kc_id, correct)` 序列，KC 走 embedding。KC 数量影响 softmax 规模；**DKT 不需要每个 KC 单独参数，但需要 KC 的 ID 稳定**，否则换 ID 要重训。
- **IRT**：题目参数（a, b）通常**按 KC 聚合**或用 KC 难度作先验，避免每题单独拟合。
- **数据结构同时服务三件事的最小接口**：
  - **出题**：`sections(kc_id) → items`（题目必须显式挂 KC，多对多；一道题可测多个 KC，用主 KC + 副 KC 区分）
  - **诊断**：`attempts(user_id, item_id, kc_id, correct, ts, latency, hints_used)` —— **必须落 kc_id 冗余**，否则每次诊断都要 join 知识树，弱端做不动。
  - **排程**：`review_queue(user_id, kc_id, due_at)` —— 排程在 **KC 级**（不是题级），题目只是 KC 的"测头"。

**一条重要工程结论**：**题目一定要能挂到 KC 上，而教材章节只能挂到 section 上**。因为教材章节是容器、KC 才是认知原子。出题的检索路径应是 `subject → volume → section → kc → items`，而不是 `section → items`。若题目只有章节归属、没有 KC 归属，**整个诊断链路是断的**——这是本项目最该先补齐的元数据。

## ②.5 自动生成方法（核心，覆盖 B5–B9）

### B5. 从教材目录/章节自动抽取知识点

**总体架构（推荐的三段式流水线）**：

```
教材原文/目录
  │
  ├─(1) 结构解析：PDF/EPUB/DOCX → 结构化段落（标题层级、正文、例题、习题）
  │      工具：PDF→text（PyMuPDF/pdfplumber/MinerU/PP-StructureV3），保留 heading level
  │
  ├─(2) LLM 抽取：分段喂入，输出**严格 schema**的 KC 候选（JSON）
  │      约束：json_schema / function calling / Outlines / vLLM guided decoding
  │
  ├─(3) 归一化与去重：别名合并、跨章同名合并、粒度校验（可测/可教/可诊断）
  │      → 人工抽检 → 入库（带 confidence 与 source）
  │
  └─(4) 题目挂载：把题库的题映射到 KC（这是诊断链路的关键，见 B8）
```

**抽取 prompt 设计要点（先验 + 工程经验）**：

1. **给层级、给范围、给上限**。不要说"抽取所有知识点"——要说"这是《人教版数学七年级上》第 2 章第 3 节的正文，请抽取 **3–7 个**知识点，覆盖该节全部可考内容"。**不给数量上限是过抽取的头号原因**。
2. **先做"段落→候选"再做"候选→归并"两阶段**，不要一次性从整册抽全树。**按小节抽 = 上下文可控 + 可并行 + 出错可局部重跑**。
3. **强制 schema**：用 JSON Schema 约束字段（见 §2.3），要求模型**只输出该 schema**，禁止自由发挥的 `type` 值——枚举用 `enum` 写死在 schema 里。
4. **让模型输出 `evidence`（原文引文）+ `confidence`**：`evidence` 必须是从原文**逐字复制**的片段。**这是最有效的幻觉抑制手段**——无法引原文的候选直接丢。
5. **few-shot 用"同教材、邻近章节"的已人工确认样本**，不要用跨学科的样例（学科语感差异大）。3–5 个 shot 通常够。
6. **负例约束**：明确列出不该抽的东西——"章标题、节标题本身不是知识点"、"习题编号不是知识点"、"页面页眉页脚不是知识点"、"图表标题不是知识点"。
7. **粒度指令要写成判据而不是形容词**：把 §2.2 的 A/B/C 三条判据直接写进 prompt，并要求模型对每个候选**自评是否满足 A/B/C**。
8. **温度调低**（0–0.2），同一输入跑多次取交集/并集做**自一致性（self-consistency）**：3 次抽取，出现 ≥2 次的候选保留 → 显著降幻觉。

**已知的两大失败模式**：

- **过抽取（over-extraction）**：把正文里每个名词都当 KC，一个小节抽出 30 个"知识点"。根因是无数量约束 + 无粒度判据。**后果最严重**：KC 数 ×10，标注成本 ×10，BKT 参数爆炸。
- **幻觉（hallucination）**：编造教材里没有的知识点（模型用"课本常识"补齐）；或把课外概念混入。根因是无 `evidence` 约束、无原文锚定。**检测手段**：`evidence` 字符串必须在原文中能精确匹配（或 fuzzy 匹配 ≥ 0.9），否则判为幻觉。

**抽取后的人工校验与成本估算**（本项目预算关键）：

| 校验层级 | 方法 | 单 KC 耗时 | 说明 |
|---|---|---|---|
| L0 自动 | schema 校验 + evidence 回查 + 跨章去重 | ~0 | 全自动，能挡掉 30–50% 的低质候选 |
| L1 快审 | 人在列表里"勾选保留/删除"（不编辑文字） | **5–15 秒 / KC** | 最划算的一层，挡掉大部分过抽取 |
| L2 细审 | 改名称、调粒度、合并/拆分、补别名 | **1–3 分钟 / KC** | 只对 L1 存疑的 20–30% 做 |
| L3 专家签 | 学科教师逐条确认 + 先修边确认 | **3–8 分钟 / KC** | 只对核心章节（考纲重点）做 |

**成本量级估算（先验，供决策）**：一个学科 800 个 KC：
- L1 全量：800 × 10s ≈ **2.2 小时**（一人半天）
- L2 对 25%：200 × 2min ≈ **6.7 小时**
- L3 对 20% 核心：160 × 5min ≈ **13 小时**
→ **一个学科全流程 ≈ 20–25 人时**。若用众包/兼职按 ¥30–60/h 计，**单学科数百到千元级**。**这是可控的**；但如果粒度失控导致 KC 变成 5000 个，成本直接 ×6。

**结论**：**LLM 抽取的省钱点在"控数量"，不在"选模型"**。用便宜模型 + 严格 schema + 数量约束 + evidence 回查，往往比贵模型自由发挥更便宜也更好。

### B6. 先修关系的自动推断（三条路线）

**路线一：知识驱动（LLM / 专家语义判断）**

- **做法**：把 KC 对（A, B）喂给 LLM，问"掌握 B 是否**必须**先掌握 A？" 输出 `{is_prereq: bool, strength, confidence, reason}`。可升级为：只对**候选对**提问（不是 O(n²) 全对）。
- **候选对生成（关键优化）**：全量 KC 两两配对是 O(n²)，3000 KC = 450 万对，不可行。实际做法：
  - **同章节 / 相邻章节内的 KC 对**（先修关系绝大多数是"局部"的）
  - **embedding 近邻 Top-K**（语义相关才可能先修）
  - **共现过滤**：只对在同一道题的解题步骤里共同出现的 KC 对提问
- **prompt 要点**：① 明确"先修"定义（**没有 A 就无法理解/完成 B**，而非"A 与 B 相关"）；② 强制 `strength: hard|soft` 区分；③ 给正反例（"加法→乘法"是 hard prereq；"加法→减法"是 soft/对称关系）；④ **要求给出"如果没有 A 会怎样失败"的一句话**（拒答率与准确率都会提升）。
- **可靠性**：先验上，LLM 在**学科常识型**先修关系上表现好（数学、物理的层递关系明显），在**教材特有的编排顺序**上易错（它不知道这本教材把哪个概念提前了）。→ **LLM 判断的是"认知真相"，教材给的是"教学顺序"，两者要分开存**（这正好对应 §2.1 的 prereq 边 vs 章节顺序）。

**路线二：数据驱动（从答题序列/作答矩阵挖掘）** —— 这是最"硬"的证据

已知代表性方法（待核实细化）：

- **概率关联规则挖掘（probabilistic association rules）**：从学生表现数据推技能先修结构。核心思想是"若学生掌握了 B 却**总是**没掌握 A → A→B 不成立；若掌握 A 的学生大多也掌握 B 且反向不成立 → 支持 A→B"。代表工作：[Discovering Prerequisite Structure of Skills through Probabilistic Association Rules Mining](https://hal.sorbonne-universite.fr/hal-01212873v1/datacite)（Labat 等，2015，HAL）✅ 一手。
- **基于可解释学习者模型**：Allègre, Yessad, Luengo, *Discovering prerequisite relationships between knowledge components from an interpretable learner model*, EDM 2023 ✅（见 [Prerequisite Relation Learning: A Survey and Outlook](https://dl.acm.org/doi/10.1145/3733593) 参考文献）。
- **教材文本中的"预备性关系"识别**：Adorni 等 *Towards the identification of propaedeutic relations in textbooks*, AIED 2019；以及 **PRET**（Prerequisite-enriched terminology, CLiC-it 2018）✅ 一手（同上综述引用）。
- **综述入口**：**[Prerequisite Relation Learning: A Survey and Outlook](https://dl.acm.org/doi/10.1145/3733593)**（ACM Computing Surveys, 2025）——把方法分成四类并汇总了开放数据集与评测指标，**这是本主题最好的单一入口** ✅ 一手。

**数据驱动的方法学要害**：

- **需要大量作答数据才能可靠**。冷启动阶段**拿不到**——这正是本项目要做"三路线混合 + 人工校"的原因。
- **混淆因素**：学生会"猜对"（guess）和"漏对"（slip）；题库覆盖不均会让"掌握"判定失真。→ 用 BKT/DKT 估计的**掌握概率**而非原始正确率作为输入（即先估掌握状态，再做关联规则），这也是上述 2015 年工作用 "evidence model" 先行估计概率知识状态的原因。
- **A→B 的数据模式判据（可直接实现）**：
  - 支持度：`P(A|B) = 掌握 B 的学生中掌握 A 的比例` —— 高
  - 反例率：`P(B|A)` —— 显著低于 `P(A|B)`（不对称性才是先修的标志）
  - **不对称性** `lift = P(A|B) / P(B|A)` 越大越像先修边
  - 注意：`P(A|B)` 高也可能是"两者都被更基础的 C 决定"（伪相关）→ 需要**条件独立性检验**（控制其他 KC 后再看）

**路线三：文本/结构驱动（教材顺序、共现、引文）**

- **教材章节顺序**：同章内 KC 按出现顺序连成链（弱先修），跨章按章节序连边（更弱）。**优点**：零成本、覆盖全；**缺点**：把"编排顺序"误当"认知先修"（教材可能为了趣味把某概念提前"感性认识"）。
- **共现（co-occurrence）**：同一道题的解题步骤、同一段落、同一例题中出现的 KC 对 → 关联边候选；**同段落中"先出现且被定义为前置"的信号**可升格为先修候选。
- **引文/定义依赖**：定义 B 时用到了 A 的术语（"因式分解"定义里出现"整式乘法"）→ 强先修信号。这可由 **术语在定义句中的出现** 自动检测。
- **建议**：把三路线做成**证据投票**，每条边记 `evidence` 集合与 `confidence`；只有**≥2 类证据**支持的边才升为 `hard`。

### B8. 知识图谱的质量评估

**四类指标（缺一不可）**：

1. **覆盖率（Coverage）**：
   - **考纲覆盖率**：抽取的 KC 中，**能对应到课程标准/考纲条目**的比例。做法：把考纲条目作为查询，检查是否有 KC 命中（可用 embedding 相似度 + LLM 判定）。目标 **≥ 90%** 的考纲条目有至少一个 KC 对应。
   - **教材覆盖率**：教材小节中**有 KC 挂载**的比例（防止整节漏抽）。目标 **100%** 的 section 至少 1 个 KC。
   - **题目覆盖率**：题库中有 KC 归属的题目比例。**这是最该先冲的指标**，目标从当前值冲到 **≥ 85%**。
2. **一致性（Consistency）**：
   - **DAG 校验**：先修图**无环**（有环必有错边，检测到环就要人工裁决）。
   - **与教材顺序的冲突率**：先修边方向与教材出现顺序矛盾的边占比。**不是零容忍**（教材可以乱序），但冲突率 > 20% 说明整体有系统性问题。
   - **与测验数据的一致性**：若数据表明"掌握 B 的学生大量不掌握 A"，这条 A→B 边应被降级/删除（可自动化成"数据否决"规则）。
   - **粒度一致性**：KC 的 `est_learn_minutes` 分布 + 题目数分布是否存在长尾异常（如某 KC 挂 200 道题 = 粒度过粗）。
3. **专家抽检（Sampling Audit）**：
   - **抽样方案**：分层随机抽样（按章节/学科分层），每层抽 20–30 个 KC；每个 KC 由 **2 位独立评审**判断"是/否合格 KC"与"先修边是否正确"。
   - **指标**：**合格率**（precision）与**漏抽率**（用盲抽教材段落，检查是否有该抽未抽，估 recall）；评审不一致用 **Cohen's κ** 衡量，κ < 0.6 说明判据定义不清，要回炉改 prompt 与判据。
   - **成败线（建议）**：KC 精度 ≥ 0.9，先修边精度 ≥ 0.85，DAG 无环。
4. **与考纲对照 / 下游指标（最有说服力）**：
   - **预测效度**：用建好的 KC 标签跑 BKT/DKT，看 **AUC / RMSE / 预测正确率** 是否比"按章节粗标签"更好。**这是知识树质量的终极检验**——树好不好，看它能不能预测学生下一题。
   - **诊断可用性**：能否对已知的错题给出合理的根因 KC（用教师标注的错因做对照）。

**迭代闭环**：抽取 → 指标评测 → 定位问题（哪一章 precision 低）→ 改 prompt/补充 few-shot → 重跑该章。**按章节局部迭代，不要全量重跑**。

### B9. 图的存储与查询（跨 Windows / Android / iOS / ESP32）

**四种方案取舍**：

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **Neo4j**（图数据库） | Cypher 表达力强，图查询天然高效，可视化好 | **服务端进程重**，无法在 Android/iOS/ESP32 跑；移动端要联网查询；运维成本 | **只在后台/服务端**做抽取、审核、图分析 |
| **SQLite**（节点表+边表+递归 CTE） | **全平台可跑**（Windows/Android/iOS 原生支持；ESP32 有可用的轻量 SQLite 或替代）；单文件、事务、离线天然支持；递归 CTE 可做先修祖先/后代查询 | 深递归查询比原生图库慢（但对 ≤5000 节点的树完全够）；无内建图算法（需自己实现拓扑排序/根因传播） | **客户端首选**（本项目的核心选择） |
| **JSON（树文件）** | 极简、易裁剪、易 diff、ESP32 可解析（ArduinoJson 等）；适合"下发一份 subtree" | 查询要全量加载；无索引；大图内存吃紧 | **弱端下发格式**（ESP32 / 一次性打包的离线包） |
| **RDF / SPARQL** | 语义标准、可与 EDUKG 等外部本体对齐、推理能力 | 工具链重、移动端支持差、开发效率低 | 只在需要**与外部知识图谱互操作**时考虑，本项目**不建议**作为主存储 |

**推荐架构（两层 + 一个交换格式）**：

```
服务端（抽取/审核/图分析）：Neo4j 或 PostgreSQL(+递归CTE)  ← 可选，甚至 JSON+Git 也够
                     │
                     │ 构建期导出（build-time export）
                     ▼
        ┌────────────┴─────────────┐
   全量包 SQLite（客户端）     分片 JSON（弱端）
   Windows/Android/iOS       ESP32 单词机
```

**跨端裁剪（本项目最关键的设计约束）**：

- **裁剪单位是 `section`（单元）**，不是 KC。因为用户的动作是"选学科/部分"，粒度和 UI 天然对齐。
- **裁剪要闭包化先修边**：只下发 section S 的 KC 会**丢掉前置依赖**。正确做法：下发 `S 的 KC ∪ S 中每个 KC 的传递先修祖先（transitive prereq ancestors）`，但祖先只下发**摘要字段**（id/name/bloom），不下发全部题目与讲解。这样弱端才有诊断所需的 DAG。
- **ESP32 的现实约束**（先验）：Flash 与 RAM 有限、无完整文件系统语义（视方案而定）、建议**扁平数组 + 定长索引**：
  - KC 表：`id(u16), name(字符串池偏移), bloom(u8), difficulty(u8), flags(u8), prereq_start(u16), prereq_count(u8)`
  - 字符串池：所有名称拼在一个 blob 里，用偏移索引（省重复字典开销）
  - 先修边：连续 CSR 数组（`prereq_index[kc] → slice`），**天然无指针、可 mmap/顺序读**
  - **目标体积**：500 KC + ~800 边 + 名称池 ≈ **30–80 KB**（完全可塞进 ESP32 flash）
- **同步与 ID**：客户端 SQLite 用同一套 `kc_id`（字符串），**永不在端上重新编号**；端上可另建 `local_int_id` 映射表加速。同步只传**增量**（`schema_version` + 变更日志）。

**查询模式（客户端必须支持的三类）**：
1. **按容器取**：`section → KCs → items`（普通索引查询）
2. **先修闭包**：某 KC 的全部传递先修祖先（SQLite 递归 CTE，或导出时预计算物化表 `kc_ancestors(kc_id, ancestor_id, depth)`）
3. **薄弱点定位的个性化查询**：`user_mastery WHERE mastery < θ` ⨝ 先修闭包（找"下游没掌握且上游也没掌握"的边界节点）

> **强烈建议**：把 `kc_ancestors` 作为**构建期物化表**导出。它体积是 O(KC × 平均祖先数)，对 5000 KC 通常 < 10 万行，但**让移动端不用做递归查询**——这是性能与实现难度上最划算的一步。

### C10. 冷启动：没有题目数据时如何先建树

**明确回答：可以先建树，而且必须先把树建出来——因为题目要挂到 KC 上，没有树就无法结构化题库。**

冷启动三阶段：

1. **阶段 0（零数据，1–2 天/学科）**：只用**教材目录 + 章节正文**做 LLM 抽取。
   - 目录给出 L2–L4 容器骨架（不需要 LLM，直接解析目录层级）
   - 正文按小节抽取 L5 KC（§B5 流程）
   - 先修边**只靠文本/结构驱动**（教材顺序 + 定义术语依赖）+ LLM 语义判断
   - **此时树的置信度全靠抽取质量，不要指望数据驱动**
2. **阶段 1（有题目，无作答）**：把已有题库（用户说"已储备题目"）**批量挂 KC**。做法：把 KC 的名称/别名/keywords + 题目题干一起给 LLM 做多标签分类；人工只审"不确定"的。**此时树第一次获得"可测性"验证**——挂不上题的 KC 就是粒度有问题（太细/不可测）→ 回炉调整。**阶段 1 是树的第一次真实体检。**
3. **阶段 2（有作答）**：跑 BKT/DKT → 掌握度 → 用**数据驱动先修推断**修正/新增边 → 用"数据否决"删掉与数据矛盾的边。**这是树从"看起来对"变成"证明对"的阶段。**

**冷启动的加速技巧**：
- **优先做"高价值子树"**：先建考纲重点章节 / 用户最常学的章节，不要追求全学科齐整。
- **借助公开图谱做初始化**（Marble os-taxonomy / MOOCCubeX / EDUKG 的概念集合做**候选种子**），再用自有教材对齐。
- **人工先画"骨架先修边"**：学科专家花 2 小时在纸上画 30–50 条主干先修边（如"整数运算→分数运算→代数式"），LLM 只在骨架内部补细节。**这条投入产出比最高**。

### C11. 版本化与演进：改版如何不破坏学习记录

**核心矛盾**：教材改版 / 树修订会改变节点，但用户的作答记录、掌握度、复习排程**都挂在 KC ID 上**。ID 一变，历史全丢。

**解决原则：KC ID 与"教材位置"解耦，且 ID 只增不删。**

1. **ID 生成规则（必须与内容无关）**：
   - **推荐**：`kc_id = "kc_" + 不可逆短哈希(学科 + 首次创建时间戳 + 随机盐)` —— **内容改了 ID 也不变**。
   - **或**：单调递增整数（`kc_000123`）+ 全局注册表（服务端发号）。
   - **绝对不要**用 `md5(名称)` 或 `学科-章-节-序号` 之类**依赖内容或位置**的 ID——改名/改版即断链。
2. **变更操作必须是"软操作"**：
   - **拆（split）**：老 KC `A` 保持 `active=true` 但标记 `superseded_by=[A1,A2]`；历史掌握度**按题目重新分配**给 A1/A2（若无题区分，则**复制**给两者并标注"继承"）。**这就是"单调细化原则"的兑现方式**。
   - **合（merge）**：新建 KC `B`，把老 KC `A1,A2` 标 `superseded_by=B`；历史掌握度**加权合并**（按作答次数加权平均）。
   - **改名/改别名**：只改 `name`/`aliases`，**ID 不动**——这直接叫"改版无感"。
   - **移动容器**（教材改版把 KC 从第 3 章挪到第 4 章）：**只改 `section_id`，ID 不动**。→ 这是 §2.1「目录树与知识 DAG 分离」的直接回报。
   - **弃用（deprecate）**：`active=false`，**永不物理删除**（保留以便老客户端与历史记录解析）。
3. **多版本共存**：`schema_version` + `textbook_version` 字段；客户端声明自己支持的版本，服务端下发对应视图（导出时按版本生成不同 SQLite）。
4. **变更日志与回滚**：所有结构性变更写入 `kg_changelog(ts, op, from_ids, to_ids, reason, operator)`。**没有变更日志，一次误操作就永久污染用户数据。**
5. **用户可见的"学习记录连续性"**：合并/拆分时算一次**掌握度迁移映射表**，把老 ID 的掌握度投到新 ID。老客户端仍用老 ID → 服务端在上报时**实时映射**。

### C12. 用户「不会什么」的定位：薄弱点定位与根因分析

**问题重述**：学生做错题 B，可能是**B 本身不会**，也可能是**先修 A 不会**（甚至 A 的先修 A' 不会）。要定位到"最该补的那一个"。

**算法：先修根因定位（Prerequisite Root-Cause Localization）**——这是 04 文档"先修 DAG"的落地算法：

核心思想：**从错误的 KC 出发，沿先修边向上游搜索，找到"最低的未掌握边界"（lowest unmastered frontier）**。若上游 A 也没掌握，那么补 B 是无效的（学生缺的是 A），应先补 A。若上游全部掌握而 B 错，则 B 是真缺口。

伪代码见 §⑤-算法3。

**关键设计点**：
- **用概率而非布尔**：`mastery(A)` 是 0–1 的概率，用**阈值 + 置信**双条件（`m < 0.6 且 attempts ≥ 3` 才算"确实没掌握"），避免偶然答错导致误判。
- **打分而非单一答案**：输出**排序的候选根因列表**（带分数），而不是一个结论——给教学策略留余地。
- **考虑"瓶颈节点"（bottleneck）**：如果 A 是 B 和 C 的共同先修，且 B、C 都错，则 A 的嫌疑**大幅提升**（多个下游失败的共同先修 = 强证据）。这是**图的全局信号**，单个 KC 的掌握度看不到。→ 这是知识树相对"平铺标签"的核心价值。
- **区分 hard/soft 先修**：hard 边阻断才判"根因"；soft 边只做加权，不动结论。
- **常见反向错误**：把"学生还没学 A"当成"没掌握 A"。→ 要用 `exposure`（是否已学/练过该 KC）区分**未学**与**不会**，这两者的教学动作完全不同。

### C13. 与复习排程对接

**核心结论：排程应在 KC 级做，而不是卡片级。** 理由：卡片是 KC 的"测头"，同一 KC 多张卡片的记忆强度是**同一件事**；若按卡片排程，会出现"同一个知识点被 5 张卡反复考"，浪费且干扰真实掌握度估计。

- **KC 级 FSRS**：每个 `(user, kc)` 维护 FSRS 的记忆状态（`stability S`、`difficulty D`、`last_review`），公式见 04 文档；作答得到 grade（Again/Hard/Good/Easy）后更新 S/D 并算 `due_at`。
  - **难点**：同一 KC 的题目难度不同，grade 映射到 FSRS 前应做**按题难度归一化**（用 IRT 的 b 或题目的历史正确率）。否则"简单题答对"被当成"记忆强"。
  - 先验提示：FSRS 家族已演进到 FSRS-6/FSRS-7 等版本（社区讨论见 [Bunpro 社区帖](https://community.bunpro.jp/t/fsrs-for-bunpro-please/138711/113) ⚠️ 二手），落地应**锁定一个版本并固定参数**，不要追逐最新。
- **先修 DAG × ZPD 的选题策略（可落地规则）**：
  1. **先修门禁**：只有当 KC 的**全部 hard 先修** `mastery ≥ θ_ready`（如 0.8）时，才把它放进"可学/可测"集合。
  2. **到期优先**：在可学集合中取 `due_at ≤ now` 的（复习），按 `overdue` 时长排序。
  3. **ZPD 选题**：新学 KC 时，选**当前掌握度在 0.3–0.7 区间**的目标（既非已会也非完全不会）——也可用**预测正确率≈0.7–0.85** 的题（IRT/PFA 预测）。
  4. **交错（interleaving）**：同一 session 内跨 KC 交错出题，而非单 KC 连做（对数学/语言均有实验支持）。
  5. **每日预算上限**：`min(到期数, 新学配额, 时间预算/平均题时)`；ESP32 单词机这类场景要**严格限量**（通勤 5–10 分钟就是全部预算）。
  6. **失败回退**：某 KC 连续 3 次失败 → **沿先修边向上游回退**（直接调用 C12 根因定位），而不是继续重复出同 KC 的题。

```sql
PRAGMA foreign_keys = ON;

-- ========== 容器层（目录树，可能随教材改版而变） ==========
CREATE TABLE subject (
  subject_id TEXT PRIMARY KEY,
  name TEXT NOT NULL, name_en TEXT
);
CREATE TABLE volume (
  volume_id TEXT PRIMARY KEY,
  subject_id TEXT NOT NULL REFERENCES subject(subject_id),
  grade INTEGER, term INTEGER,
  name TEXT NOT NULL,
  textbook_name TEXT, publisher TEXT, edition TEXT
);
CREATE TABLE chapter (
  chapter_id TEXT PRIMARY KEY,
  volume_id TEXT NOT NULL REFERENCES volume(volume_id),
  ordinal INTEGER NOT NULL, name TEXT NOT NULL
);
CREATE TABLE section (
  section_id TEXT PRIMARY KEY,
  chapter_id TEXT NOT NULL REFERENCES chapter(chapter_id),
  ordinal INTEGER NOT NULL, name TEXT NOT NULL,
  est_minutes INTEGER DEFAULT 40,
  -- 冗余：便于"选学科/部分"一步到位
  volume_id TEXT NOT NULL REFERENCES volume(volume_id),
  subject_id TEXT NOT NULL REFERENCES subject(subject_id)
);
CREATE INDEX idx_section_chapter ON section(chapter_id, ordinal);

-- ========== 知识层（KC，ID 必须稳定） ==========
CREATE TABLE kc (
  kc_id TEXT PRIMARY KEY,               -- 永不变的 opaque id
  name TEXT NOT NULL,
  name_en TEXT,
  parent_kc_id TEXT REFERENCES kc(kc_id),
  section_id TEXT REFERENCES section(section_id),  -- 可改（改版挪章）
  subject_id TEXT NOT NULL REFERENCES subject(subject_id),
  volume_id TEXT REFERENCES volume(volume_id),
  kc_type TEXT NOT NULL CHECK (kc_type IN ('concept','skill','fact','principle','method')),
  bloom TEXT NOT NULL CHECK (bloom IN ('remember','understand','apply','analyze','evaluate','create')),
  difficulty REAL DEFAULT 0.5,
  discrimination REAL,
  item_types TEXT,                       -- JSON array 字符串
  assessable INTEGER NOT NULL DEFAULT 1,
  est_learn_minutes INTEGER DEFAULT 15,
  keywords TEXT,                         -- JSON array
  examples TEXT,                         -- JSON array
  source TEXT,                           -- JSON（含 evidence / extractor / page）
  confidence REAL DEFAULT 0.0,
  review_status TEXT NOT NULL DEFAULT 'auto'
    CHECK (review_status IN ('auto','llm_verified','human_checked','expert_signed')),
  active INTEGER NOT NULL DEFAULT 1,
  superseded_by TEXT,                    -- JSON array of kc_id
  schema_version INTEGER NOT NULL DEFAULT 3,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_kc_section ON kc(section_id) WHERE active = 1;
CREATE INDEX idx_kc_parent  ON kc(parent_kc_id);
CREATE INDEX idx_kc_volume  ON kc(volume_id, active);

CREATE TABLE kc_alias (
  kc_id TEXT NOT NULL REFERENCES kc(kc_id),
  alias TEXT NOT NULL,
  alias_type TEXT DEFAULT 'synonym',     -- synonym | abbrev | mistake_name
  PRIMARY KEY (kc_id, alias)
);
CREATE INDEX idx_alias_text ON kc_alias(alias);

-- ========== 边（统一表） ==========
CREATE TABLE kg_edge (
  edge_id INTEGER PRIMARY KEY AUTOINCREMENT,
  edge_type TEXT NOT NULL CHECK (edge_type IN ('prerequisite','related','synonym','confusable')),
  from_id TEXT NOT NULL,
  to_id TEXT NOT NULL,
  strength TEXT CHECK (strength IN ('hard','soft')),
  weight REAL DEFAULT 0.5,
  evidence TEXT,                         -- JSON array: textbook_order/llm_semantic/data_mined/expert
  confidence REAL DEFAULT 0.0,
  notes TEXT,
  active INTEGER NOT NULL DEFAULT 1,
  UNIQUE (edge_type, from_id, to_id)
);
CREATE INDEX idx_edge_from ON kg_edge(edge_type, from_id) WHERE active = 1;
CREATE INDEX idx_edge_to   ON kg_edge(edge_type, to_id)   WHERE active = 1;

-- 构建期物化的先修闭包：让移动端/弱端免做递归查询（强烈建议导出）
CREATE TABLE kc_ancestors (
  kc_id TEXT NOT NULL, ancestor_id TEXT NOT NULL,
  depth INTEGER NOT NULL, via_hard INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (kc_id, ancestor_id)
);
CREATE INDEX idx_anc_ancestor ON kc_ancestors(ancestor_id);

-- ========== 题目 ↔ KC（诊断链路的命门） ==========
CREATE TABLE item (
  item_id TEXT PRIMARY KEY,
  item_type TEXT NOT NULL,
  stem TEXT, answer TEXT,
  difficulty_b REAL, discrimination_a REAL, guess_c REAL,
  source TEXT, created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE item_kc (
  item_id TEXT NOT NULL REFERENCES item(item_id),
  kc_id   TEXT NOT NULL REFERENCES kc(kc_id),
  role TEXT NOT NULL DEFAULT 'primary',  -- primary | secondary
  weight REAL DEFAULT 1.0,
  PRIMARY KEY (item_id, kc_id)
);
CREATE INDEX idx_itemkc_kc ON item_kc(kc_id);

-- ========== 变更日志（保命） ==========
CREATE TABLE kg_changelog (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts TEXT NOT NULL, op TEXT NOT NULL,     -- add|rename|move|split|merge|deprecate|edge_add|edge_del
  from_ids TEXT, to_ids TEXT,
  reason TEXT, operator TEXT, kg_version TEXT
);

-- ========== 运行时：掌握度（绝不写回知识树本体） ==========
CREATE TABLE user_mastery (
  user_id TEXT NOT NULL,
  kc_id   TEXT NOT NULL,
  mastery REAL NOT NULL DEFAULT 0.0,      -- 0..1
  model TEXT NOT NULL DEFAULT 'bkt',      -- bkt|dkt|elo|irt
  attempts INTEGER NOT NULL DEFAULT 0,
  correct  INTEGER NOT NULL DEFAULT 0,
  exposure INTEGER NOT NULL DEFAULT 0,    -- 是否学过/练过（区分"未学"与"不会"）
  p_learn REAL, p_guess REAL, p_slip REAL,  -- BKT 参数（可选，便于多端一致）
  fsrs_stability REAL, fsrs_difficulty REAL,
  last_seen_at TEXT, due_at TEXT,
  origin_device TEXT,
  updated_at TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (user_id, kc_id)
);
CREATE INDEX idx_mastery_due   ON user_mastery(user_id, due_at);
CREATE INDEX idx_mastery_weak  ON user_mastery(user_id, mastery) ;

-- ========== 作答流水（诊断与数据驱动先修推断的原料） ==========
CREATE TABLE attempt (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT NOT NULL,
  item_id TEXT NOT NULL,
  kc_id   TEXT NOT NULL,                  -- 冗余，避免每次 join
  correct INTEGER NOT NULL,
  latency_ms INTEGER, hints_used INTEGER DEFAULT 0,
  grade INTEGER,                          -- FSRS 1..4
  ts TEXT NOT NULL,
  device TEXT
);
CREATE INDEX idx_attempt_user_kc ON attempt(user_id, kc_id, ts);
CREATE INDEX idx_attempt_ts      ON attempt(ts);
```

## ④ 知识点抽取与先修推断方法对比表

### 4.1 知识点（KC）抽取方法

| 方法 | 依赖 | 准确率 / 成本 | 适用场景 | 备注 |
|---|---|---|---|---|
| **人工专家标注** | 学科教师、时间 | 精度最高（≈1.0）；**成本最高**（3–8 min/KC） | 核心章节、考纲重点、终审 | 不可全量；作为 **golden set** 校准其他方法 |
| **目录/结构规则解析** | 教材目录层级（PDF 书签/DOCX 样式） | 容器层精度高；**KC 层几乎为零**（目录只有节标题） | 生成 L2–L4 骨架 | 零成本、必做；**它给不了 KC** |
| **LLM 单段抽取（严格 schema + 数量约束 + evidence 回查）** | LLM API + 原文分段 | 精度 **0.75–0.9**（经 evidence 回查后）；成本 **≈0.01–0.1 元/KC** | **主路线**，全量初抽 | 必须配 §B5 的 8 条 prompt 要点 |
| **LLM 多轮自一致性（self-consistency ×3 取交集）** | 3× LLM 调用 | 精度 **+5~10 pt**，召回略降；成本 ×3（仍很便宜） | 关键章节 | 降幻觉最划算的一招 |
| **LLM + few-shot（同教材邻近章节已确认样本）** | 3–5 个人工样本/学科 | 精度 **+5~15 pt**；成本不变 | **强烈推荐** | 样本要同教材同语感 |
| **微调小模型 / 抽取式模型（BERT-BiLSTM-CRF 等）** | 数千条标注 + 训练 | 精度可超通用 LLM；前期标注成本高 | KC 量大（>5000）且需反复重抽时 | 本项目第一版**不需要** |
| **术语表/知识点清单反查** | 已有考纲词汇表、课标附录 | 精度高但**覆盖率低** | **校验用**（查漏） | 与 LLM 结果取补集 = 漏抽候选 |
| **公开图谱种子对齐**（Marble / MOOCCubeX / EDUKG） | 第三方概念集合 | 提供**候选种子**，需与自有教材对齐 | 冷启动加速、交叉验证 | **不可直接导入**（学段/教材不匹配） |

**结论**：**第一版 = 结构规则（容器）+ LLM 单段抽取 + evidence 回查 + few-shot + 人审 L1**。这是成本/质量的最优点。

### 4.2 先修关系推断方法

| 方法（路线） | 依赖 | 准确率 / 成本 | 适用场景 | 备注 |
|---|---|---|---|---|
| **LLM 语义判断（知识驱动）** | LLM + 候选对；prompt 给"先修"定义 + hard/soft + 必须解释失败原因 | 学科常识型 **0.7–0.85**；教材编排型易错；成本 **≈0.001–0.01 元/对** | 冷启动**主力**；候选对由同章/近邻/共现过滤 | Marble 的做法正是 LLM 判断 + `reason` 留痕（已核实） |

| **可解释学习者模型（数据驱动）** | 作答数据 + 可解释模型 | EDM 2023 报告有效；依赖数据量 | 与上者互补 | [综述](https://dl.acm.org/doi/10.1145/3733593) |
| **认知诊断模型恢复先修（数据驱动）** | 作答数据 + DINA/神经网络 | 神经网络**恢复先修关系比 DINA 更准**（阿尔伯塔学位论文） | 有 CDM 基础时 | 需 Q 矩阵 |
| **教材章节顺序（结构驱动）** | 目录/正文顺序 | 覆盖 100%、成本≈0；**精度低（0.5–0.65）**，把"编排顺序"当"认知先修" | 冷启动**兜底**、生成候选 | 只作弱证据（soft） |
| **共现统计（结构驱动）** | 同一段落/例题/解题步骤 | 中间；易受伪相关影响 | 生成候选对、补充 related 边 | 需条件独立性检验剔除伪相关 |
| **定义术语依赖（结构驱动）** | 定义句中的术语引用 | 精度较高（**0.7–0.8**）；需术语识别 | 数学/理科定义链 | "定义 B 时用到 A 的术语"→ 强信号 |
| **引文/课标依赖（结构驱动）** | 课标条目的前后置表述 | 精度高、覆盖低 | 与考纲对照校验 | 课标语言本身就是先修宣言 |
| **混合证据投票（推荐）** | 以上全部 | 最优：**≥2 类证据才升 hard** | **本项目应采用** | 每条边记 `evidence` 数组 + `confidence` |

**关键提示**：**先修边的"强度"比"是否存在"更重要**。Marble 用 `hard/soft` 二分 + 一句 `reason` 就够用——**别追求数值权重，追求可解释与可复核**。

```python
                      few_shot=load_few_shot_same_textbook(),      # ★ 3-5个同教材样本

                       response_format={"type":"json_schema","json_schema":KC_SCHEMA})

    merged = majority_intersection(outputs, key=lambda kc: normalize(kc["name"]), min_votes=2)

        if kc["confidence"] < 0.6:
            kc["review_queue"] = "L2"        # 进人工细审
        kept.append(kc)
    return kept, merged_prereqs(outputs)
```

### 算法 2：先修关系推断（三路线证据投票）

```python
def infer_prerequisites(kcs, sections, item_kc, attempts_optional=None):
    E = {}   # (from,to) -> {evidence:set, confidence:[]}

    # ---------- 候选对生成（避免 O(n^2)） ----------
    cand = set()
    for s in sections:                                        # 同节内全连
        cand |= pairs(s.kc_ids)
    for a, b in adjacent_sections(sections):                  # 相邻节
        cand |= cross_pairs(a.kc_ids, b.kc_ids)
    cand |= embedding_topk_pairs(kcs, k=8)                    # 语义近邻
    cand |= cooccurrence_pairs(item_kc, min_count=3)          # 同题/同步共现

    # ---------- 路线三：结构驱动（成本 0，先跑） ----------
    for (a, b) in cand:
        # 教材顺序：a 出现在 b 之前
        if order_index(a) < order_index(b):
            add_evidence(E, a, b, "textbook_order", conf=0.5)
        # 定义依赖：b 的定义句里用到了 a 的术语
        if a.term_in_definition_of(b):
            add_evidence(E, a, b, "textbook_order", conf=0.8)

    # ---------- 路线一：LLM 语义判断（主力） ----------
    for (a, b) in cand:
        r = llm_judge(LlmPrereqPrompt, a, b)                  # 返回 {is_prereq,strength,conf,reason}
        if r.is_prereq:
            add_evidence(E, a, b, "llm_semantic", conf=r.conf, strength=r.strength, reason=r.reason)
        # ★ 同时问反向，做不对称性检查：a→b 与 b→a 都判为真 = 可能是 related 而非 prereq
        r2 = llm_judge(LlmPrereqPrompt, b, a)
        if r.is_prereq and r2.is_prereq:
            downgrade_to_related(E, a, b)

    # ---------- 路线二：数据驱动（有作答才跑） ----------
    if attempts_optional is not None:
        mastery = estimate_mastery_bkt_or_dkt(attempts_optional)   # 先估知识状态
        for (a, b) in cand:
            p_a_given_b = P(mastery[a] > .7 | mastery[b] > .7)
            p_b_given_a = P(mastery[b] > .7 | mastery[a] > .7)
            n = support_count(a, b)
            if n < 30: continue                                    # 样本不足，不下结论
            lift = (p_a_given_b + EPS) / (p_b_given_a + EPS)
            if p_a_given_b > 0.8 and lift > 1.5:
                if conditional_independence_ok(a, b, mastery):      # ★ 剔除伪相关
                    add_evidence(E, a, b, "data_mined", conf=min(0.9, 0.5 + lift/5))
            elif p_b_given_a > 0.8 and lift < 0.67:
                # ★ 数据否决：与 A→B 矛盾
                veto_edge(E, a, b)

    # ---------- 投票定级 ----------
    edges = []
    for (a, b), ev in E.items():
        kinds = ev["evidence"] - {"vetoed"}
        if "vetoed" in ev["evidence"]: continue
        hard = ("data_mined" in kinds) or ("expert" in kinds) or (len(kinds) >= 2 and "textbook_order" in kinds)
        edges.append(Edge(a, b,
                          strength="hard" if hard else "soft",
                          weight=mean(ev["confidence"]),
                          evidence=sorted(kinds),
                          confidence=mean(ev["confidence"])))
    edges = break_cycles(edges)          # ★ 必须：拓扑排序找环 → 环内最低置信边降级为 soft 或删除
    return edges
```

**破环策略**：找 SCC（强连通分量）→ 在环内保留**置信度最高**的边链，其余降级 `soft`；若降级后仍有环，删除**证据种类最少**的边，并写入 `kg_changelog` 等人工裁决。

### 算法 3：先修根因定位（"用户到底不会什么"）

```python
def locate_root_causes(user_id, failed_kcs, graph, mastery, theta=0.6, min_attempts=3):
    """
    输入：本次测评失败的 KC 集合；输出：排序的候选根因 KC 列表（带分数与解释）
    思路：从失败节点沿先修边向上游搜索，找"最低的未掌握边界"。
          多个下游失败的共同先修 → 嫌疑显著提升（瓶颈信号）。
    """
    upstream = defaultdict(lambda: {"support": [], "bottleneck": 0.0})

    for kc in failed_kcs:
        # 收集所有传递先修祖先（构建期已物化 kc_ancestors）
        for anc, depth, via_hard in graph.ancestors(kc):
            m = mastery.get(anc, 0.0)
            att = mastery.attempts(anc)
            # 区分"未学"与"不会"
            if mastery.exposure(anc) == 0:
                upstream[anc]["support"].append((kc, depth, "not_exposed"))
                continue
            if m < theta and att >= min_attempts:
                upstream[anc]["support"].append((kc, depth, "unmastered"))
            if via_hard and depth == 1:
                upstream[anc]["bottleneck"] += 1.0        # 直接 hard 先修权重更高

    # ---- 打分 ----
    results = []
    for anc, info in upstream.items():
        mastered_support = len(info["support"])
        if mastered_support == 0: continue
        m = mastery.get(anc, 0.0)
        gap = max(0.0, theta - m)                          # 缺口大小
        # 瓶颈度：被多少个失败的 KC 共同依赖（归一化）
        bottleneck = info["bottleneck"] / max(1, graph.downstream_count(anc, failed_kcs))
        # 邻近度：越靠近失败节点越可能是直接原因（depth 小 → 权重高）
        proximity = mean(1.0 / (1 + d) for _, d, _ in info["support"])
        # 可达性：该 KC 的 hard 先修是否都已掌握（若上游还有更深的缺口，应继续往上）
        ready = all(mastery.get(p, 0.0) >= theta for p in graph.hard_prereqs(anc))

        score = 0.40*gap + 0.30*bottleneck + 0.20*proximity + (0.10 if ready else -0.15)
        results.append(RootCause(kc=anc, score=score, mastery=m, gap=gap,
                                 evidence=info["support"],
                                 reason=explain(anc, info["support"], bottleneck, ready)))

    results.sort(key=lambda r: -r.score)
    # ★ 只返回"最低的未掌握边界"：若某根因的上游还有未掌握的先修，把它作为更高优先级的候选排在前面
    return results[:5]
```

```python
def build_today_session(user, now, budget_minutes=10, theta_ready=0.8):
    G = knowledge_graph_of(user.subject)
    # 1) 先修门禁：候选 KC 必须其全部 hard 先修已掌握
    ready = [kc for kc in G.kcs()
             if all(user.mastery(p) >= theta_ready for p in G.hard_prereqs(kc))]
    # 2) 到期复习（KC 级 FSRS）
    due = [kc for kc in ready if user.due_at(kc) <= now]
    due.sort(key=lambda kc: -(now - user.due_at(kc)))          # 越逾期越优先
    # 3) ZPD 新学：掌握度 0.3–0.7 的 KC，且其"下游可解锁数"高者优先
    zpd = [kc for kc in ready if 0.3 <= user.mastery(kc) <= 0.7]
    zpd.sort(key=lambda kc: -G.downstream_count(kc))           # 解锁更多的先学
    # 4) 交错（interleaving）：从多个 KC 轮流取题，不连做同一 KC
    queue, t = [], 0
    while t < budget_minutes:
        pool = due or zpd
        if not pool: break
        kc = pick_max_gap(pool, exclude_recent=queue[-3:])     # 最近 3 题不重复 KC
        item = select_item(kc, target_p_correct=0.78)          # 用 IRT 预测选最接近目标的题
        queue.append(item); t += item.est_seconds / 60
    return queue

def on_answer(user, item, correct, grade, now):
    for kc, w in item.kc_weights():                            # 一题可测多个 KC，按权重更新
        st = user.fsrs_state(kc)
        st = fsrs_update(st, grade, item_difficulty_norm=normalize(item.difficulty_b))
        user.set_due(kc, now + st.interval)                    # ★ 排程挂在 KC 上
        user.update_mastery(kc, bkt_update(user.mastery(kc), correct,
                                           item.slip, item.guess), weight=w)
    # 连续失败 → 触发根因定位并回退到上游
    for kc in item.kc_ids():
        if user.consecutive_fail(kc) >= 3:
            causes = locate_root_causes(user.id, [kc], G, user.mastery)
            if causes and causes[0].kc != kc:
                user.enqueue_remediation(causes[0].kc)
```

### 算法 5：ID 稳定化与变更迁移

```python
def new_kc_id(subject_id):
    # opaque、内容无关、单调唯一；跨端同步只传这个串
    return "kc_" + base62(sha256(f"{subject_id}|{uuid4()}|{time.time_ns()}")[:10])

def split_kc(old_id, new_kcs, mastery_table, item_kc, changelog):
    """拆分：老 KC 保留但弃用，历史掌握度按题目归属迁移；无法区分则复制"""
    assignable = {n.id: [] for n in new_kcs}
    for item in item_kc.of(old_id):
        target = llm_route_item_to_new_kc(item, new_kcs)        # 或人工
        assignable[target].append(item)
    for n in new_kcs:
        items = assignable[n.id]
        if items:
            mastery_table[n.id] = weighted_mastery(old_id, items)   # 按题迁移
        else:
            mastery_table[n.id] = mastery_table[old_id]             # ★ 复制并标注"继承"
            mastery_table[n.id].inherited_from = old_id
    mark_superseded(old_id, [n.id for n in new_kcs])
    changelog.log(op="split", from_ids=[old_id], to_ids=[n.id for n in new_kcs])

def merge_kcs(old_ids, new_id, mastery_table, changelog):
    total = sum(mastery_table[i].attempts for i in old_ids) or 1
    mastery_table[new_id] = weighted_mean(
        [mastery_table[i].mastery for i in old_ids],
        weights=[mastery_table[i].attempts for i in old_ids])
    for i in old_ids: mark_superseded(i, [new_id])
    changelog.log(op="merge", from_ids=old_ids, to_ids=[new_id])

def rename_kc(kc_id, new_name, new_aliases):
    """改名：只改 name/aliases，ID 与所有历史记录不动 —— 改版无感的根源"""
    db.execute("UPDATE kc SET name=?, updated_at=datetime('now') WHERE kc_id=?", (new_name, kc_id))
    db.executemany("INSERT OR IGNORE INTO kc_alias(kc_id,alias) VALUES (?,?)",
                   [(kc_id, a) for a in new_aliases])
```

### 算法 6：质量评估（覆盖率 / 一致性 / 抽检 / 下游指标）

```python
def evaluate_kg(kg, items, syllabus, attempts=None):
    rep = {}
    # 覆盖率
    rep["section_coverage"] = pct(sections_with_kc(kg))                       # 目标 1.00
    rep["syllabus_coverage"] = pct(syllabus_items_matched(kg, syllabus, sim=0.8))  # 目标 ≥0.90
    rep["item_coverage"]    = pct(items_with_primary_kc(items))               # 目标 ≥0.85
    # 一致性
    rep["dag_acyclic"]      = not has_cycle(kg.prereq_edges())                # 必须 True
    rep["order_conflict"]   = pct(edges_conflicting_with_textbook_order(kg))  # 关注 <0.20
    rep["granularity_outliers"] = count_granularity_outliers(kg, items)       # 一个KC挂>50题 / <3题
    if attempts is not None:
        rep["data_contradiction"] = pct(edges_with_mastery_contradiction(kg, attempts))
    # 专家抽检（外部输入）
    rep["audit"] = {"kc_precision": None, "prereq_precision": None, "kappa": None}
    # 下游指标（终极检验）
    if attempts is not None:
        rep["kt_auc_kc_tree"]  = cross_val_auc(attempts, labels="kc_tree")
        rep["kt_auc_chapter"]  = cross_val_auc(attempts, labels="chapter_only")
        rep["kt_auc_delta"]    = rep["kt_auc_kc_tree"] - rep["kt_auc_chapter"]  # ★ 树的价值证明
    return rep
```

**判据（建议上线门槛）**：`dag_acyclic == True` 且 `kc_precision ≥ 0.90` 且 `prereq_precision ≥ 0.85` 且 `item_coverage ≥ 0.85`。

## ⑥ 坑与风险

| # | 坑 | 症状 | 根因 | 对策 |
|---|---|---|---|---|
| 1 | **粒度过细** | 一个 KC 出不出 3 道题；BKT 每 KC 4 参数，参数不可辨识；掌握度曲线几乎完全相关 | LLM 无数量约束 + 无判据 → 把每个名词都当 KC | 硬性 `maxItems`、A/B/C 判据入 prompt、`>10 KC/节` 自动重跑；**单调细化原则**（只拆不合），第一版故意偏粗 |
| 2 | **粒度过粗** | 诊断只能给"整章不会"；复习整章重来 | 直接用教材小节当 KC | 用"可测性 ≥3 题"反向校验；一个 KC 挂 >50 题强制拆分 |
| 3 | **LLM 幻觉** | 教材里没有的知识点；课外概念混入 | 无原文锚定 | `evidence` 逐字复制 + fuzzy ≥0.9 回查；无证据即丢；自一致性取交集 |
| 4 | **过抽取** | 一个小节 30 个"知识点" | 同 1 | 数量上限 + 负例清单（章标题/习题号/页眉页脚/图注都不抽） |
| 5 | **ID 不稳定** | 教材改版/改名/挪章 → 用户历史全部失联 | 用 `md5(name)` 或"章-节-序"当 ID | **opaque 稳定 ID**（内容无关、只增不删）；改名只动 `name/aliases`；挪章只动 `section_id`；弃用不删除 + `superseded_by` + `kg_changelog` |
| 6 | **把"目录顺序"当"认知先修"** | 先修边大面积与真实认知矛盾；越往后学越乱 | 教材可为了趣味提前"感性认识"某概念 | 目录顺序只作 `soft` 弱证据；`hard` 需 ≥2 类证据或专家；教材顺序与认知先修**分开存** |
| 7 | **先修图有环** | 拓扑排序失败；"先学哪个"无解；根因定位死循环 | LLM 判断不一致（A→B 且 B→A） | 双向提问做不对称性检查（都真 → 降级为 `related`）；构建期 SCC 破环 + 变更日志 |
| 8 | **数据驱动先修的伪相关** | 出现 A→B 但实际是共同先修 C 导致 | 未做条件独立性检验 | 先估知识状态再挖关联；`P(A\|B)/P(B\|A)` 不对称性 + 条件独立性 + 最小样本量 30 |
| 9 | **运行时数据污染知识树** | 一人一份树；跨端同步冲突 | 把 `mastery` 写进 KC 本体 | **知识树本体与运行时表严格分表**（见 §2.3/2.5）；本体只读下发，运行时只在 `user_mastery` |
| 10 | **跨端裁剪丢失先修** | 只下发当前 section → 弱端无法做根因定位 | 按容器切分而不做先修闭包 | 下发 `section KC ∪ 传递先修祖先（仅摘要字段）`；构建期物化 `kc_ancestors`；弱端用 CSR 扁平数组 |
| 11 | **弱端体积/性能失控** | ESP32 flash 装不下；移动端递归查询卡 UI | 直接下发全图/全量题目 | 分片下发（按 section）、字符串池 + 偏移索引、CSR 先修数组、摘要祖先不含题目；**500 KC ≈ 30–80 KB** |
| 12 | **标注成本失控** | 人力预算爆表、进度卡死 | KC 数太多 + 全量细审 | 分层校验（L0 自动 → L1 快审 5–15s → L2 细审 → L3 专家只碰核心）；**先审下游影响最大的（被引用最多）KC** |
| 13 | **题目没有 KC 归属** | 诊断链路完全断开（只能按章出题） | 题库只标了章节 | **最高优先级的补齐项**：批量 LLM 挂 KC + 人审不确定项；目标 item_coverage ≥0.85 |
| 14 | **混淆"未学"与"不会"** | 把没教过的 KC 判为薄弱点，教学动作做错 | 只看 mastery 不看 exposure | `user_mastery.exposure` 字段；根因输出里区分 `not_exposed` / `unmastered` |
| 15 | **公开图谱直接导入的幻觉** | 数据与自有教材不匹配（学段/地区/版本） | 误以为公开 K-12 图谱可直接用 | 公开图谱只作**对照/种子/校验**；许可逐个确认（学术用途 ≠ 可商用分发） |
| 16 | **版本化缺变更日志** | 一次误操作永久污染用户数据 | 直接原地改树 | `kg_changelog` 全量留痕 + 掌握度迁移表 + 可回滚 |
| 17 | **评测只做"看起来对"** | 树上线后诊断效果差但查不出原因 | 无下游指标 | 必跑 `kt_auc_delta`（KC 树 vs 章节粗标签）——**不能提升预测力的树就是白建的** |
| 18 | **追新 FSRS 版本** | 参数漂移、历史复习计划被打乱 | 跟随社区最新版本 | **锁定一个 FSRS 版本与参数**（→ 待核实具体版本号）；grade 需按题难度归一化后再喂 FSRS |

## ⑦ 对本项目的 5 条可落地建议

**建议 1：第一版这样建树最快（2 周内出可用树，单学科）**

```
Day 1–2  │ 解析教材目录 → 生成容器骨架（学科/册/章/节），零 LLM，纯规则
         │   产出：section 表（含 volume_id/subject_id 冗余）
Day 3–5  │ 按小节 LLM 抽取 KC（§⑤算法1）：严格 schema + 2–7 个上限
         │   + evidence 回查 + 3 次自一致性 + 同教材 few-shot
         │   产出：KC 候选（review_status=auto/llm_verified）
Day 5–6  │ 人工 L1 快审（5–15 秒/KC，全量）
         │   产出：KC 定稿，review_status=human_checked
Day 6–7  │ 先修边：结构驱动（教材顺序/定义依赖）+ LLM 判断 + 双向不对称检查 + 破环
         │   再花 2 小时请学科老师画 30–50 条主干 hard 边做锚点
         │   产出：prereq 边（hard 需 ≥2 类证据）
Day 8–11 │ 【最关键】把已有题库批量挂 KC（LLM 多标签 + 人审不确定项）
         │   目标 item_coverage ≥ 0.85 —— 没有这一步，诊断是断的
Day 12–14│ 导出三件套：① 客户端 SQLite（全量）② 弱端裁剪 JSON（按 section + 先修闭包摘要）
         │   ③ 质量报告（§算法6）；跑一次 kt_auc_delta（此时可用小样本作答）
```

**核心纪律**：**容器骨架（规则，便宜）→ KC（LLM，便宜）→ 人审 L1（全量，可负担）→ 题目挂 KC（必做）**。不要一开始就做全学科、不要一开始就细粒度、不要一开始就追求先修边完美。

**建议 2：先做"题目→KC 挂载"，它就是知识树的第一次体检**
用户已有"按章节区分的资料与题目"。**只要题目还没挂 KC，知识树就无法驱动诊断**。倒过来说：**挂载过程会暴露树的粒度问题**——挂不上题的 KC（太细/不可测）和抢题的 KC（太粗）都会自动浮出来。建议把"挂载成功率"当作第一版树的核心验收指标，而不是"知识点个数"。

**建议 3：把 `hard/soft` + `reason` 做成硬规范（Marble 已验证的做法）**
已核实的 `os-taxonomy`（1,590 概念 / 3,941 条边）证明这套最简 schema 足以支撑一个开源 DAG 产品：`{topicId, prerequisiteId, strength: hard|soft, reason: 一句人话}`。**照抄这个形状**，并要求每条边必须有 `reason`——`reason` 是人工复核的入口，也是 LLM 判断质量的可见证据。同时学它用 **opaque 稳定 ID**（`mt__00ZSLnB7p`），而不是"第几章第几节"。

**建议 4：存储选型 = 服务端 Neo4j（可选）+ 客户端 SQLite + 弱端 CSR 二进制；先物化 `kc_ancestors`**
- **服务端**：抽取/审核/图分析用 Neo4j 或直接用 SQLite/Postgres；不必强上图库。
- **客户端（Windows/Android/iOS）**：**SQLite**。DEXA 2026 的研究显示，深度 ≤3 的子图查询 **SQLite 实际快于 Neo4j**（874s vs 8,757s），"嵌入式关系库不够用"是伪焦虑。
- **弱端（ESP32）**：**CSR 扁平数组 + 字符串池**的 JSON/二进制包，按 section 分片，含传递先修**摘要**；目标 **30–80 KB / 500 KC**。
- **务必在构建期物化 `kc_ancestors`**：把递归查询变成一次索引查找，这是移动端流畅度的性价比最高的一步。

**建议 5：排程与诊断都锚在 KC 上，并用 `kt_auc_delta` 守住质量**
- **排程**：KC 级 FSRS（不按卡片排程），grade 先按题难度归一化；先修门禁（hard 先修 ≥0.8 才解锁）+ ZPD（0.3–0.7）+ 交错出题 + 每日预算上限（ESP32 场景尤其要严）。
- **诊断**：算法 3 的"先修根因定位"，输出**排序候选 + 人话理由**（而不是一个黑箱标签），并区分**未学 vs 不会**。
- **质量红线**：定期跑 `AUC(KC 树) − AUC(章节粗标签)`。**若这个差 ≤0，说明知识树没有带来增量信息，必须回头改树而不是改算法。** 同时锁死 `dag_acyclic == True`、`item_coverage ≥ 0.85`、专家抽检 KC 精度 ≥0.90 三条门槛。
