# 08 · 人机互学双向闭环（本项目最有想象力的差异化方向）

> 调研时间：2026-10-26 ｜ 定位：对应文档 05 的**空位 3**——「人的学习」与「AI 的学习」目前是两个互不相通的孤岛，本项目有机会把它们接进**同一个反馈回路**。
> 说明：学习科学的算法基础（FSRS / BKT / IRT 等）见文档 04；本文只讲**「双向」这件事本身**。

---

## 一、一句话结论

**这个想法不是我们首创——学界已有明确的名称与初步证据：「Learning by Teaching（LbT，边教边学）」。**
NeurIPS 2024 已证明 **LLM 通过「教学生」来提升自己**是可行的（例如 M1 把 GPT-4o 在 MATH 上的准确率从 **87.84% 提升到 96.69%**），且给出三条可操作发现。这意味着我们的差异化不是「发明概念」，而是**把它工程化到一个个人可跑、跨设备、可审计的系统里**——而这恰恰是学术工作没有做的部分。

---

## 二、证据基础

### 2.1 LLM 侧：LLM 确实能「边教边学」

**《Can LLMs Learn by Teaching for Better Reasoning? A Preliminary Study》**
Xuefei Ning, Zifu Wang, Shiyao Li, Zinan Lin, Peiran Yao, Tianyu Fu, Matthew B. Blaschko, Guohao Dai, Huazhong Yang, Yu Wang（清华大学 NICS-efc 实验室等）— **NeurIPS 2024**
- 论文：<https://proceedings.neurips.cc//paper_files/paper/2024/hash/8340b085045cf13f1f0b6c2c4cc0a89c-Abstract-Conference.html>
- 代码：<https://github.com/imagination-research/lbt> ｜ 网站：<https://sites.google.com/view/llm-learning-by-teaching>

**核心动机**（与我们的诉求完全一致）：
> 人类教育中，教学不仅提升学生，也提升老师——促使老师形成更严谨清晰的推理与更深的知识建构。**如果 LLM 也能 LbT，我们就有可能在不完全依赖人类数据或更强模型的前提下，持续提升模型。**

**三个方法（对应 LbT 的三个层级）**：
| 方法 | 层级 | 做什么 | 是否需要训练 |
|---|---|---|---|
| **M1** | L1 · 观察学生反馈 | 观察学生（弱模型）的学习反馈来改进自己的答案 | ❌ 免训练，仅提示 |
| **M2** | L2 · 从反馈中学习 | 从反馈中学习 | 需微调 |
| **M3** | L3 · 迭代学习 | 迭代地在反馈中学习 | 需微调 |

**三条可操作发现**（这是最有工程价值的部分）：
1. **LbT-TMQ 假设**：「**让学生更容易学会的教学材料，其逻辑更清晰、更准确**」——即**「可教学性」可以作为「正确性」的代理信号**。这给了我们一把**免外部裁判的自评尺子**。
2. **弱到强泛化（weak-to-strong）**：**通过教弱模型，可能反过来提升强模型**——个人设备上算力弱，反而可以当「学生」来反哺强的教师模型。
3. **学生多样性有帮助**：**教多个学生可能优于只教一个学生，甚至优于只让老师自己学**。

**已核实的关键数字**：**M1 把 GPT-4o 在 MATH 数据集上的准确率从 87.84% 提升到 96.69%**（来源：<https://nicsefc.ee.tsinghua.edu.cn/nics_file/pdf/d6935896-f13e-47c8-87ba-a3fbb6f974e6.pdf>）。
> ⚠️ 注意：这是**免训练、仅靠提示**取得的提升，说明该回路的**边际成本极低**，非常适合放在 P1/P2 阶段先验证。

### 2.2 人类侧：教别人确实提升自己（Protégé Effect）

- **元分析证据**：Kobayashi（2019, *Japanese Psychological Research*）汇总 **28 项研究**，合并效应量 **准备教学 g = 0.35**、**准备并实际教学 g = 0.56**；另有 Ribosa & Duran（2022, *Educational Research Review*）的综述（来源汇总：<https://glasp.co/articles/protege-effect>，**二手整理，需回原始文献核实**）。
- ⚠️ **方法学警告（必须写进我们的评估设计）**：该元分析**仅用 Rosenthal's fail-safe N 评估发表偏倚**，而该方法**已被广泛批评**。所以效应量应视为**乐观上界**，我们自己的系统必须**做真实的前测/后测/延迟测试**，不能引用文献数字当结论。
- 现象名：**Protégé Effect（门徒效应）**——学生为「别人的利益」学习时投入更多。

### 2.3 双向性的教育技术侧

| 工作 | 贡献 | 链接 |
|---|---|---|
| **Bidirectional Feedback-Based Personalization of Learning using Multi-tier AI**（AAAI SS 2025） | 提出**三层框架**实现「human-AI 个性化闭环」，**以真实人类反馈为根基**，并在真实课堂评估效果 | <https://ojs.aaai.org/index.php/AAAI-SS/article/view/35553> |
| **Bidirectional Co-regulation Mechanisms Between Teachable Agents and Students**（AIED 2026） | 用 **1013 条有效对话序列**刻画「AI 教导权威 vs 学生自主性」的动态平衡，并关联前后测学习增益 | <https://dl.acm.org/doi/10.1007/978-3-032-29763-1_14> |
| **Teaching a Conversational Agent using Natural Language**（2026） | 可教学对话智能体（agent 扮演新手），激发 Protégé Effect，提升投入与认知结果 | <https://www.sciencedirect.com/science/article/pii/S1560429226000284> |
| **Teaching LLMs Naturally: Pedagogical Strategies for Interactive Knowledge Acquisition**（2026） | 研究 LLM 在**在线场景**中动态获取复杂知识的困难，与教学法策略 | <https://dl.acm.org/doi/10.65109/JGLB4831> |
| **CoTutor**（IEEE 2026） | 用**信号处理技术增强 BKT**（贝叶斯知识追踪），做编程教育的自适应反馈 | <https://ieeexplore.ieee.org/document/11398809> |

**结论**：双向性在**教育学**里已被研究了几十年（Protégé effect），在 **LLM** 里刚被证明可行（LbT）。**但把两者接到同一个系统、同一份账本上，并用同一套指标度量「人变强了没有 + AI 变强了没有」——这一层是空的。**

## 三、闭环设计：把两个学习者接进一个回路

### 3.1 概念图

```
                    ┌──────────────── 共同的知识图谱（唯一真相源）────────────────┐
                    │        概念 · 先修关系 · 掌握度(人) · 技能库(AI)            │
                    └───────┬───────────────────────────────────────┬────────────┘
                            │                                       │
              ┌─────────────▼─────────────┐           ┌─────────────▼─────────────┐
              │      人（学生/使用者）      │           │        AI（智能体）        │
              │  复习 · 作答 · 讲解 · 纠错  │           │  检索 · 生成 · 执行 · 反思  │
              └─────────────┬─────────────┘           └─────────────┬─────────────┘
                            │                                       │
            「人教 AI」：人向 AI 解释概念      「AI 教人」：AI 生成讲解/出题
            人的讲解被 AI 当作教学材料          人的作答正确率 = AI 的即时裁判
                            │                                       │
                            └──────────────┬────────────────────────┘
                                           ▼
                          ┌────────────────────────────────┐
                          │   双向信号汇聚 → 统一证据账本     │
                          │  · 人在知识点 k 上的掌握度变化    │
                          │  · AI 在技能 s 上的表现变化       │
                          │  · 相关性与因果归因（谁帮了谁）    │
                          └───────────────┬────────────────┘
                                          ▼
                          ┌────────────────────────────────┐
                          │  采纳协议 adopt/reject（见文档06）│
                          │  技能版本 / 复习排程 / 提示词演化  │
                          └────────────────────────────────┘
```

### 3.2 四条可实现的耦合通路

**通路 A：人的错题 → AI 的技能缺口**（最易实现）
- 人在知识点 k 反复出错 → 标记对应 AI 技能 s 为「讲解无效」→ 触发 s 的 **replay/mutation**（SkillEvo 范式，见文档 05 §3.2）。
- 这直接解决了**冷启动无数据**问题：**人的学习行为就是第一份训练信号**。

**通路 B：AI 的讲解 → 人的复习排程**（用成熟算法）
- AI 生成讲解 → 人作答 → 用 **FSRS/BKT** 估计掌握度 → 排下一次复习（详见文档 04）。
- 这是**纯粹的应用既有算法**，风险极低，建议最先做。

**通路 C：人教 AI（LbT 的本地化）**——本项目的灵魂
- 人向 AI 解释一个概念 → 该解释作为「教学材料」喂给一个**学生模型**（本地小模型）→
  - 依 **LbT-TMQ 假设**，「让学生更容易学会的材料逻辑更清晰准确」→ **用学生的表现反推人的解释质量**。
  - 依 **弱到强泛化**：本地弱模型当学生，反哺更强的教师模型。
  - 依 **学生多样性**：用**多个不同的学生模型**（不同参数量/量化档/不同 prompt）来评价同一份解释 → 比单一学生更稳健。
- **副产品**：这一通路天然产生 Protégé Effect（人因为「在教 AI」而更投入）——**激励与算法合一**。

**通路 D：跨设备的经验互教**
- 设备 A 上学到的技能/解释，作为「教学材料」传给设备 B（**传教学材料而非梯度**，与文档 03 的结论一致）→ 依 LbT 结论，**这本身可能也提升发送方**（因为要「教得清楚」，必须先把逻辑理清）。

### 3.3 统一度量（关键：两个学习者用同一把尺子）

| 对象 | 主要指标 | 来源 |
|---|---|---|
| **人** | 掌握度提升、**延迟测试保留率**、迁移测试正确率 | 学习科学（文档 04） |
| **AI** | `ACC`、**遗忘 `F`**、学习曲线 `AULC`、工具效率 `TUE` | 持续学习指标（文档 06） |
| **交互（新增，本项目独有）** | **可教学性分数**（学生模型的即时学习增益）、**反哺增益**（人教 AI 后 AI 的表现提升）、**双向留存**（双方向增益是否随时间保持） | 本文（基于 LbT-TMQ 假设） |

> **「可教学性分数」是本项目最值得申请的原创度量**：它把一个**主观的「你讲清楚了吗」变成客观的「学生模型学会了多少」**，且不需要人类标注、不需要外部裁判、完全本地可算。这恰好绕开了文档 06 §五列的 reward hacking 风险（因为裁判是确定性可复现的学生模型，而非 LLM 自评）。

## 四、为什么这个方向特别适合「去中心化 + 跨平台 + 个人」

| 特征 | 为什么契合 |
|---|---|
| **不需要大量算力** | LbT 的 M1 是**免训练仅提示**的；教学材料评价用**本地小模型**即可 |
| **天然分布** | 不同设备 = **不同的学生**（异构算力恰好提供「学生多样性」，而这被证明对 LbT 有帮助） |
| **数据自产** | 人机互动自动产生训练信号，**无需爬数据、无隐私外泄**（数据不出本地） |
| **可验证** | 有确定性判据（学生模型的学习增益 + 人的答题正确率），**不依赖 LLM 自评** |
| **有护城河** | 学术侧只做了概念验证，**工程化 + 个人设备适配 + 长期账本**是空白 |
| **伦理可控** | 提升的是**使用者自己**的学习与人机协作质量，而非无人监督的自我复制 |

## 五、风险与反证（必须正视）

| 风险 | 说明 | 应对 |
|---|---|---|
| **LbT 证据仍属「初步研究」** | 论文标题即含 "A Preliminary Study"，主要验证 MATH 等推理基准 | 先做小规模复现，不要当既定事实；把「能否复现」列为 P1 的验收标准 |
| **学生模型太弱 → 信号无区分度** | 若学生怎么教都学不会，「可教学性分数」就退化为噪声 | 设**学生能力下限**，并做**多学生一致性检验** |
| **LLM 版本漂移** | 换一个模型/一次更新，历史分数可能全部不可比 | **冻结评估用的学生模型与其量化档**，作为长期基准并版本归档 |
| **人可能「假装教」** | 人会为刷分而生成看起来很教学化的文本 | 交叉验证：可教学性分数必须与**人自己的延迟测试成绩**相关，否则不采信 |
| **Protégé Effect 效应量被高估** | 元分析的发表偏倚方法学有缺陷 | **不引用文献效应量作为效果预期**；只认自己的前测/后测/延迟测试 |
| **教学相长的边界** | 教 AI 可能让人**过度简化**（为迁就学生而牺牲严谨） | 记录「简化 vs 严谨」两种模式，并分别测人对**难题**的迁移能力 |
