# 多端构建指南

WORDO 的目标是「同一套 core + 同一份账号域，跑在多种终端上」。本页说明各端的构建现状与步骤，并**如实标注哪些已在本机验证、哪些尚未实际构建**。

---

## 现状一览

| 端 | 技术 | 状态 |
|---|---|---|
| Windows 桌面 | Tauri 2 + WebView2 | **已支持**，本机编译并启动成功 |
| Android | Tauri 2（移动端） | 给出步骤；**尚未在本机实机构建** |
| iPadOS / iOS | Tauri 2（移动端） | 给出步骤；**尚未在本机实机构建**（且需 macOS + Xcode） |
| ESP32 单词机 | 极简参考节点（非 Tauri） | 提供协议 + 可运行参考桥（`tools/mininode`）+ 固件草图（`embed/esp32-node`）；**未做硬件联调** |

> 诚实声明：本机没有 iOS/Android 的真实构建环境，移动端步骤依据 Tauri 2 官方要求整理，**未在真机或模拟器上跑通**。首次实际构建时请以 [Tauri 2 官方文档](https://v2.tauri.app/) 为准逐项核对。

## 一、Windows 桌面（已支持）

要求：Rust（MSVC 工具链）、VS Build Tools（VCTools workload + Windows SDK）、WebView2 运行时、Node.js。

```powershell
cd apps/desktop
npm install
npm run dev        # = tauri dev（开发热载）
npm run build      # = tauri build（出安装包）
```

说明：
- Windows 仅支持 **MSVC** 工具链（GNU 工具链在 Tauri 依赖栈会踩 `dlltool` / wry 的坑）。
- 中文路径下 GNU ld 会报错，仓库 `.cargo/config.toml` 已把 `target-dir` 覆盖到稳定的 C 盘目录规避。
- 应用配置在 `%APPDATA%\app.wordo.desktop\config.json`，账号域默认在 `%APPDATA%\app.wordo.desktop\domain\default`。

## 二、Android（Tauri 2 移动端）

### 所需 SDK / 工具
- **JDK 17**、**Android Studio**（含 Android SDK / Platform Tools / Build Tools）
- **Android NDK**（Tauri 2 要求）
- 环境变量：`ANDROID_HOME` / `NDK_HOME`（指向 SDK 与 NDK）
- Rust 交叉编译目标：

```powershell
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

### 通用步骤
```powershell
# 在 apps/desktop 下（Tauri CLI 已作为 devDependency 安装；也可全局装 tauri-cli ^2）
npx tauri android init       # 生成 Android 工程
npx tauri android dev        # 连真机 / 模拟器调试
npx tauri android build      # 出 APK / AAB
```

### 注意事项
- **移动端不能后台常驻**（平台事实）：Android 前台服务有累计时长限制。手机仍是完整节点，但同步发生在**打开 App 时**，而非后台常驻。这与公理 A1「节点对等」并不冲突。
- 触控与安全区：前端已用 `100dvh` + `env(safe-area-inset-*)`、底部导航 ≥48px、软键盘避让（visualViewport）。
- 首次构建前确保 WebView 相关依赖与 Gradle 版本匹配；具体以当前 Tauri 2 版本要求为准。

## 三、iPadOS / iOS（Tauri 2 移动端）

### 所需环境
- **macOS** + **Xcode**（含命令行工具）+ **CocoaPods**
- Apple 开发者账号（真机安装 / 上架需要）
- Rust 交叉编译目标：

```bash
rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
```

### 通用步骤
```bash
cd apps/desktop
npm install
npx tauri ios init
npx tauri ios dev
npx tauri ios build
```

### 注意事项
- **iOS 不能在 Windows 上构建**——必须有 macOS + Xcode，这是本机无法实际构建 iPadOS 端的直接原因。
- iOS 后台处理窗口极短（`BGProcessingTask` 约 60 秒量级），同样按「打开 App 时同步」设计。
- 安全区与 Home 条：前端已做 `safe-area-inset-*` 适配。

> `apps/mobile/README.md` 说明了移动端初始化约定。移动端可在 `apps/desktop` 上直接跑 `tauri android/ios init`，也可在 `apps/mobile` 另起工程；首次落地时请统一目录约定。
>
> **没有 Mac 时的过渡方案**：把真实前端 + 真实后端跑在局域网，用 iPad Safari 打开并「添加到主屏幕」（PWA 全屏），即可先看 iPad 真实效果；详见 [iPad 试跑说明](iPad-试跑说明.md)。前端已针对平板断点（641–900）做过适配。

## 四、ESP32 单词机（极简参考节点）

ESP32 是**极简节点**，不是完整应用：它不跑模型、不跑 Tauri，只做三件事——**取题 → 写一行 JSON → 搬运文件**。

- **取题**：从账号域 / 学科包里取一道题（离线读取已同步的题目数据）。
- **写一行 JSON**：把一次作答按账本事件格式写出一行 JSON（可含掌握度/间隔等调度结果）。
- **搬运文件**：通过 SD 卡 / USB / 局域网共享等方式，把这一行 JSON 合并回账号域，下次同步后其他设备即读到。

设计上遵守同一公理：**只追加自己的结果、不覆盖别人的文件**，从而天然无冲突；调度（间隔/掌握度）可在设备端按同一规则计算（见 [ESP32 能力边界](资料/11-ESP32单词机端能力边界.md)）。

- 节点接口与最小节点的完整协议：[docs/大纲/04-节点接口与最小节点-v0.1.md](大纲/04-节点接口与最小节点-v0.1.md)
- **可运行的参考实现**：`tools/mininode/`（导出卡片集 → 设备作答 → 入库账本，`node tools/mininode/test.mjs` 端到端自测）；**固件草图**：[embed/esp32-node/](../embed/esp32-node/)（协议映射 + Arduino 草图）
- ESP32 硬件/屏幕/语音选型边界：[docs/资料/11-ESP32单词机端能力边界.md](资料/11-ESP32单词机端能力边界.md)（其中明确 **sherpa-onnx 不支持 ESP32**，语音能力按该文档结论取舍）

> 状态：节点协议与主机侧参考桥已完成并有自测；**真实 ESP32 固件尚未上机联调**（`embed/esp32-node/main.cpp` 为需按板子适配的草图）。
