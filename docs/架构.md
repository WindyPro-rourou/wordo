# 架构

本文说明 WORDO 的三条设计公理、分层方式、账号域数据布局与同步矩阵、三端同构契约，以及关键文件索引。设计动机与调研依据见 [docs/大纲/00-总框架-v2.md](大纲/00-总框架-v2.md)。

---

## 一、三条公理

| 公理 | 含义 | 对架构的约束 |
|---|---|---|
| **A1 · 节点对等** | 没有「主服务器」，每台设备都是完整节点 | 数据不能只活在一端；同步必须是多写可合并的，而不是「上行到中心」 |
| **A2 · 内容与呈现分离 + 学科可扩展** | 内容（学科包）与呈现（壳）解耦；换学科只换内容包，不改核心 | 壳只做呈现；core 只认规范的包与账本；新学科 = 新 `packs/<id>/` 目录 |
| **A3 · 变更留痕** | 任何影响学习者状态的变化都要可审计 | 以 append-only 账本为唯一事实来源；派生视图可随时重算；删除写墓碑而非物理删除 |

这三条决定了整体形态：**一个不依赖中心、靠文本账本自洽、换内容不改代码的学习系统**。

## 二、分层：core = 契约与数据，壳 = 呈现

```
┌──────────────────────────── 壳（呈现层）────────────────────────────┐
│  桌面 Tauri 2 · 手机 Tauri 2 · 开发预览(Web)                          │
│  只做：交互、渲染、把用户动作翻译成对契约的调用                        │
└───────────────────────────────┬─────────────────────────────────────┘
                                │  同一份 JSON 契约（core/src/api.rs）
┌───────────────────────────────▼─────────────────────────────────────┐
│                       Rust core（契约与数据）                         │
│  api（契约门面）· validate（包校验）· learn（账本/调度）· chat（会话）  │
│  llm（模型调用）· outcheck（输出校验）· prompt（提示词装配）· config   │
└───────────────────────────────┬─────────────────────────────────────┘
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│              账号域目录（文本为源；放同步盘即同步）                    │
│   ledger/<node>.jsonl · chats/<id>/ · settings.md · 派生 user.md/plan  │
└─────────────────────────────────────────────────────────────────────┘
```

- **core 不做 UI**：校验、账本、调度、会话、模型调用、输出校验全部在 Rust 核心，UI 换掉不影响逻辑。
- **壳是薄封装**：Tauri 命令只是把前端请求转给 `core/src/api.rs`；前端是原生 HTML/CSS/JS。
- **文本为源**：所有数据先落文本（JSONL / MD / JSON），可读、可 diff、可迁移；SQLite 只作可重建的派生索引。

## 三、账号域数据布局

一个「账号域」就是一个目录。把它放到同步盘，就等于把这台设备接上了同步通道。

```
<账号域>/
  node.json                    本机节点身份（每台设备各自一份）
  settings.md                  个性化设置（随域同步）
  ledger/<node>.jsonl          每节点 append-only 账本（事件带单调 seq）= 唯一事实来源
  chats/<id>/meta.json         会话元信息
  chats/<id>/<node>.jsonl      会话事件（消息 / __rename 重命名 / __deleted 墓碑），读时合并去重
  wrong/<date>-<node>.md        错题委托文书（人读表格 + 机读 JSON 块）
  wrong/<date>-<node>.md.result-<by>.md   委托回执（处理方写）
  reports/周报-YYYY-MM-DD.md    导出周报（一次性产物）
  （user.md / plan 为派生视图：由账本在内存渲染，不写共享盘）
```

关键点：
- **账本是唯一事实**。掌握度、复习队列、薄弱点、计划状态都由账本按规则重算（`derive` 幂等）。
- **`user.md` 不落共享盘**：每次按账本在内存渲染后注入提示词，避免「两端各写一份 user.md」的冲突。
- **删除/重命名是事件**：写 `__deleted` / `__rename` 墓碑与事件，旧副本不会把内容「复活」，历史仍可审计。
- **会话 id 带节点后缀**：跨设备新建会话不会撞 id。

## 四、同步矩阵

「无冲突」不是靠 merge 算法，而是靠**结构**：每个节点只写自己的文件，共享的都是可合并/可重算的视图。

| 数据 | 文件 | 谁写 | 同步规则 |
|---|---|---|---|
| 账本事件 | `ledger/<node>.jsonl` | 每个节点只写自己那份 | 追加-only，互不覆盖；全体节点文件合并即全集 |
| 节点身份 | `node.json` | 每台设备 | 各设备各自持有，标识本机 |
| 个性化设置 | `settings.md` | 用户 | 文本随域同步，人工可读可合并 |
| 学习者状态 | （派生，无落盘） | core 按账本渲染 | 不写共享盘 → 天生无冲突 |
| 学习计划 | `plan`（由账本 `plan_add/plan_done` 派生；`plan.md` 已降级） | 追加事件 | 从账本派生，状态记在账本 |
| 会话 | `chats/<id>/<node>.jsonl` + `meta.json` | 每个节点只写自己那份 | 追加事件 + 墓碑/重命名，读时按解析时间合并去重 |
| 错题委托 / 回执 | `wrong/…` + `…result-<by>.md` | 导出方写委托、处理方写回执 | 一写一读，回执是独立文件，互不覆盖 |
| 周报 | `reports/周报-*.md` | 本机导出 | 一次性产物，可随域 |
| 密钥 / 模型配置 | 应用配置目录 `config.json` | 本机 | **不放进账号域、不同步**（见同步指南的注意事项） |

> seq 单调 + 重复 id 检测 + 墓碑，使「是否丢事件、是否被重放」可被自检（`verify_ledger`）。双节点并发 240 条实测 0 重复 / 0 缺口 / derive 幂等。

## 五、三端同构契约

桌面壳、CLI、开发预览共用同一套命令名与参数（`core/src/api.rs` 定义；预览用 Node 复刻同一契约）：

```
        apps/desktop/src-tauri          core CLI (main.rs)         tools/preview/backend.mjs
        （Tauri 命令，薄封装）           （wordo api <name>）       （Node 同契约复刻）
                    └──────────────────────┬──────────────────────────┘
                                           ▼
                             core/src/api.rs（唯一契约实现）
```

契约命令分组（节选）：

| 分组 | 命令 |
|---|---|
| 包与配置 | `list_packs` · `load_pack` · `get_config` · `set_config` |
| 模型 | `build_prompt` · `ask_model` |
| 学习环路 | `learn_state` · `learn_due` · `learn_queue` · `learn_answer` · `learn_sync` · `learn_delegate` · `learn_review` · `learn_plan` |
| 会话 | `chat_list/get/new/append/rename/delete` · `detect_subject` |
| 记账与导出 | `record_answer` · `record_judged` · `record_explain` · `verify_ledger` · `export_report` |

这样做的收益：改一处逻辑三端同步生效；预览测的是真契约、真 packs、真账本，不会与产品漂移。CLI 的 `wordo api <name> --json '<args>'` 让脚本与回归直接调同一契约。

## 六、关键文件索引

| 位置 | 职责 |
|---|---|
| `core/src/api.rs` | 契约门面：把校验/账本/会话/模型能力组织成统一命令 |
| `core/src/validate.rs` | 按 `subject-pack/1` 校验学科包（schema / KC 引用 / DAG 环 / 挂载率） |
| `core/src/learn.rs` | 学习环路：作答记账、掌握度、间隔调度、委托、计划、自检 |
| `core/src/chat.rs` | 会话 CRUD + 学科自动判定（`detect_subject`） |
| `core/src/llm.rs` | 唯一 HTTP 调用实现（OpenAI 兼容 /chat/completions，含重试） |
| `core/src/outcheck.rs` | 按 `output-schema/1` 校验模型输出（T1 讲解 / T2 错因 / T3 复习） |
| `core/src/prompt.rs` | 提示词装配（编译内嵌 `prompt-pack/1` + 注入 GUIDE/kc/题目索引） |
| `core/src/config.rs` | 提供方预设 + 配置读写（含 magpie 本地网关预设） |
| `core/src/model.rs` | 学科包数据模型（subject.json / KC / 先修 / 题目，宽松反序列化，具体校验在 `validate.rs`） |
| `apps/desktop/src/` | 前端（`index.html` / `app.js` / `style.css`，原生无框架） |
| `apps/desktop/src-tauri/` | Tauri 2 壳：命令薄封装 + 配置 |
| `specs/subject-pack/1/SPEC.md` | 学科包规范（目录结构、5 必需字段、树/先修/题目 schema、校验规则） |
| `specs/prompt-pack/1/PROMPT.md` | 前置提示词（五段结构 + 注入位 + few-shot） |
| `specs/output-schema/1/` | 正式 JSON Schema（explain / classify-error / review-wrong） |
| `packs/math.high` · `packs/english.high` | 两个真实学科包（各 5 KC + 3 题 + 讲解样例） |
| `tools/preview/` | 无头预览 + 真契约 Node 后端（开发/验收用，不进发布包） |
| `tools/consistency/` | 跨模型一致性度量（`run.mjs` / `self-check.mjs`） |
