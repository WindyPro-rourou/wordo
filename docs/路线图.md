# 路线图

本页记录已交付的 v1.0 与下一步方向。原则：**先证据、后宣称**——任何「变强」的说法都要等账本与度量跑通。当前项目不对自进化能力作对外宣称。

---

## 一、已交付 v1.0（2026-11-07）

- 对话式学习终端：讲解 / 出题 / 判分 / 复习建议，输出经正式 Schema 校验。
- 学科自动判定 + 手动纠错；chat-first 会话历史（新建 / 切换 / 删除 / 自动标题）。
- 三个页签：对话 / 今日 / 设置；今日页 = 复习队列 → 薄弱 → 计划 → user.md → 周报。
- 学习科学规则落地：置信度三档、蒙对不算掌握、看错题不降掌握、已掌握低频抽查、错因分型、交错练习、连续两次错换讲法。
- 数据层：账号域文本账本（单调 seq）、会话事件化（墓碑/重命名/节点后缀）、`verify_ledger` 自检；双节点并发 240 条 0 重复 / 0 缺口。
- 跨模型一致性：正式 JSON Schema + golden 用例 + 度量脚本，结构一致率 100%。
- 两个真实学科包（math.high / english.high）、CI 全绿（core 编译+测试 / 包校验 / 前端无头冒烟 / Tauri 桌面壳编译）。

> 完整交付说明与已知限制见 [docs/交付说明-v1.0.md](交付说明-v1.0.md)。

## 二、下一步

### 1）内容补齐（最高优先）

当前内容规模是 **demo 级**（两个包各 5 个知识点、3 道题）。真实使用前需要「每个知识点 5–10 道经典题」的前置建设。

- [ ] **用户自备资料 → 结构化入库管线**：把教材/讲义/真题（纯文本或截图 OCR）整理成 `packs/<subject>/` 规范结构（**不做爬虫**，只做用户提供内容的入库）。
- [ ] 题库草稿「生成 + 校验器把关 + 人工抽检」流水线：模型批量生成草稿，`validate-pack` 把关，用户抽检。
- [ ] 把现有两个包补到「可直接学」的题量，作为样板。

### 2）平台：Android / iPadOS 实机

- [ ] Android 实机构建与联调（Tauri 2 移动端，需 Android SDK/NDK + JDK 17）。
- [ ] iPadOS 实机构建（需 macOS + Xcode，本机无法构建）。
- 步骤与注意事项见 [多端构建指南](多端构建指南.md)；两端当前**均未在本机实际构建**。

### 3）ESP32 参考节点

- [ ] 固件原型：**取题 → 写一行 JSON → 搬运文件**的最小闭环。
- [ ] 协议对齐 `docs/大纲/04-节点接口与最小节点-v0.1.md`；硬件/语音边界见 [ESP32 能力边界](资料/11-ESP32单词机端能力边界.md)。

### 4）教师视图优化

- [ ] 明确学生/教师可见性（是否对学生隐藏教师视图）。
- [ ] 倾向以「导出周报给老师」为主，而非老师登录看板。
- [ ] 题库/知识树/校验报告的可用性打磨。

### 5）同步加密与多账号

- [ ] 账号域加密（当前为明文目录 + 同步盘）。
- [ ] 多账号支持与密钥托管边界。
- [ ] 明确「API Key 是否随域同步」（当前建议：**不同步**，只留本机）。

## 三、开放决策项（需你拍板）

| 编号 | 决策 | 备选 / 建议 |
|---|---|---|
| A | 内容来源 | 模型批量生成题库草稿 + 校验器把关 + 你抽检（推荐先做一个包）｜ 还是你提供题库我来结构化？是否做「用户资料→结构化」工具链（不做爬虫） |
| B | 平台优先级 | iPadOS 壳 / ESP32 单词机 / 教学工具层（画板·物理模拟）先做哪个 |
| C | 许可证 | 框架部分 PolyForm NC 1.0.0 vs Elastic License 2.0；学科包内容 CC BY-SA 4.0？ |
| D | 同步通道 | 默认引导 OneDrive / Syncthing / 局域网共享；域加密与多账号是否现在做；API Key 是否随域同步（建议不同步） |
| E | 教师视图 | 保留看板 / 改为「导出周报」/ 对学生隐藏 |

> 这些决策不阻塞现有使用，但会影响「内容规模、平台投入、许可口径」。建议先定 A（内容）与 D（同步/密钥），其余可随版本推进。
