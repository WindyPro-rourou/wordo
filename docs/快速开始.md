# 快速开始

本页给出三条路径：最快上手（无头预览，无需 Rust）、从源码构建核心与桌面壳、以及首次使用三步。所有命令在仓库根目录执行。

---

## 0. 前置要求

| 用途 | 需要 |
|---|---|
| 跑开发预览（推荐先做） | Node.js ≥ 20 + 系统自带的 Edge/Chromium（`playwright-core` 复用系统浏览器） |
| 构建 Rust 核心 / 桌面壳 | Rust 稳定工具链；Windows 下需 **MSVC**（VS Build Tools + Windows SDK）+ **WebView2** 运行时 |
| 跑一致性度量 | Node.js ≥ 20（见 `tools/consistency/`） |

> 本机若无 Rust 工具链，不影响你先用「无头预览」把界面、账本、真实学科包跑起来。

---

## 1. 最快上手：无头开发预览（无需 Rust）

预览后端 `tools/preview/backend.mjs` 用 Node 复刻了与 Rust core **同一份 JSON 契约**，读的是**真实的 `packs/` 与同格式账本**，提示词读的是同一份 `specs/prompt-pack/1/PROMPT.md`——所以预览里看到的就是产品行为。

```powershell
cd tools/preview
npm i                     # 仅依赖 playwright-core（复用系统浏览器）
node seed.mjs             # 造一个演示账号域（便于立刻看到复习队列/账本）
node server.mjs --port 4310
```

浏览器打开 <http://127.0.0.1:4310> 即可。

预览目录里还带了自迭代 / 验收脚本（开发用，不进发布包）：`shoot.mjs`（多视口巡检）、`ai-test.mjs`（端到端真调模型）、`interact.mjs`（交互回归）、`test-p1p2.mjs` / `test-concurrency.mjs` / `test-sci.mjs` / `test-rules.mjs`（账本、并发、学习科学、SRS 规则）。

## 2. 从源码构建 Rust 核心（CLI）

```powershell
cd core
cargo build                       # 产物为 target/debug/wordo
```

> 注意：仓库内 `.cargo/config.toml` 可能把 `target-dir` 覆盖到 `C:/wordo-build/target`（用于绕开 Windows 中文路径下 GNU ld 的问题）。以该配置为准，实际产物以 `cargo build` 打印的路径为准。

常用 CLI（在 `core/` 或指向二进制）：

```powershell
wordo validate-pack packs/math.high          # 校验学科包（0 错误才算过）
wordo inspect-pack packs/math.high           # 打印包的树 / 题目 / 统计
wordo prompt      --task explain ...         # 只装配提示词，便于审阅
wordo ask         ...                        # 真调模型（含 schema 校验 + 重试）
wordo learn-state / learn-due / learn-queue / learn-answer / learn-session
wordo api <name> --json '<args>'             # 直接调用内部契约（脚本/回归用）
```

多数命令支持 `--domain`（账号域目录）、`--packs`（学科包目录）、`--node`（扮演某个节点身份，便于多节点演练）。

## 3. 桌面打包（Tauri 2）

```powershell
cd apps/desktop
npm install
npm run dev        # = tauri dev，开发热载
npm run build      # = tauri build，产出桌面安装包
```

前端是**原生 HTML/CSS/JS**（`apps/desktop/src/`，无框架），后端命令只做薄封装调 `core/src/api.rs`。

## 4. 首次使用三步

**① 配模型**
设置页选择提供方并填 Base URL / API Key / 模型，或用「自定义（OpenAI 兼容）」接任意兼容端点。内置预设：本地网关（magpie）、NVIDIA NIM、DeepSeek、Kimi、通义千问、OpenAI。
- 配置写在应用配置目录 `%APPDATA%\app.wordo.desktop\config.json`（**不在仓库内**，可用环境变量 `WORDO_CONFIG` 改路径）。
- 模型名请以 `GET /v1/models` 实测为准——预设里列出的模型可能已 EOL。

**② 新建或选学科**
在对话页直接说第一句话即可，系统按「知识点名 > 学科名 > 包 id > 简称」自动判定学科（例如「讲讲一般过去时」→ 高中英语）。判定错了点顶栏学科胶囊手动纠错即可，纠错只追加事件、不改历史。

**③ 开始学**
- 「讲讲 XX」→ 讲解卡 + 检测题；「给我出两道题」→ 按账本（到期 → 薄弱）出题；「我该复习什么」→ 读账本给建议；「混合练 3 个薄弱点」→ 交错练习。
- 每题判完即写账本；「今日」页汇总复习队列、薄弱点、学习计划与用户状态，可「导出周报」。

> 账号域默认在 `%APPDATA%\app.wordo.desktop\domain\default`（可用 `WORDO_DOMAIN` 改）。把这个目录放进同步盘即等于接上同步，见 [同步指南](同步指南.md)。

## 常见问题（FAQ）

**Q：没有 API Key 能用吗？**
能打开界面、看知识树/账本，但「讲解 / 出题 / 判分」需要模型。可配置任一 OpenAI 兼容提供方；本地已有 magpie 网关时直接用 `http://127.0.0.1:3425/v1`。

**Q：模型填了却报 410 / 模型不存在？**
说明该模型已下线。用 `GET /v1/models` 查实当前可用清单再填，不要凭记忆。

**Q：电脑没装 Rust，能不能跑？**
能——用第 1 节的「无头开发预览」。桌面壳与 CLI 才需要 Rust（Windows 下还需 MSVC + WebView2）。

**Q：Windows 编译报中文路径错误 / dlltool 找不到？**
用 **MSVC** 工具链而非 GNU；仓库 `.cargo/config.toml` 已把 `target-dir` 指到稳定的 C 盘目录规避中文路径问题。

**Q：数据是明文吗？会不会冲突？**
账号域是文本目录、目前**未加密**；同步靠「每节点只追加自己的文件 + 派生视图」，结构上不冲突，无需 merge 算法。注意**不要把密钥写进账号域目录**（密钥属本机应用配置）。

**Q：模型输出为什么会「不合格重试」？**
输出经 `specs/output-schema/1/` 的正式 Schema 校验，不合格会重试；注入该知识点的预置讲解素材后首轮通过率明显提升——素材是输出稳定的关键输入。

**Q：跨模型一致性怎么自己复现？**
见 `tools/consistency/run.mjs`（度量）与 `self-check.mjs`（自一致性基线），口径见 [docs/评审/一致性报告-2026-11-07.md](评审/一致性报告-2026-11-07.md)。
