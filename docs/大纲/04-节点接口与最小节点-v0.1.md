# 节点接口与最小节点 v0.1

> 去中心化的判定标准：**任何一个节点，只要能读账本、能追加自己的账本，它就是完整节点**。
> 形态只决定「怎么用」，不决定「能不能用」（公理 A1）。ESP32 单词机就是这条契约的极限样本。

## 一、节点必须会的三件事（最小契约）

| 能力 | 输入 | 输出 | v0 实现 |
|---|---|---|---|
| ① 取题 | 知识点 id | 题目（含选项、答案） | 读 `packs/*/items/*.json`，或 `POST` 到任一节点 |
| ② 作答落账 | 题目 id + 我的选项 | **追加**一行到 `ledger/<我>.jsonl` | `wordo learn-answer` |
| ③ 参与同步 | 账号域目录 | 合并后的状态 | `wordo learn-sync`（读全部账本 + 重算 user.md） |

**只有 ①②③**，没有第四件事。这意味着：
- ESP32 单词机只需「取题 + 写一行 JSON + 把文件传出去」，不需要理解讲解、不需要渲染 markdown、不需要联网调用模型；
- 手机（安卓/iPadOS）与桌面做同一套事，只是呈现更丰富；
- 谁都可以发委托，谁都可以处理委托（无主从）。

## 二、一条作答事件的线格式（最小节点唯一要会写的格式）

```json
{"id":"<毫秒-序号-节点>","ts":"<RFC3339>","node":"<节点名>","kind":"answer",
 "pack":"english.high","item_id":"it_eng_0001","kc_ids":["kc_eng_0002"],
 "answered":"A","correct":"B","ok":false,"source":"device"}
```

约束：
- `id` 只需**全局唯一**（毫秒+序号+节点名即可），不要求 UUID；
- 只追加，**永不修改**已写行 → 冲突不可能发生；
- 字段缺省即空，读取端一律按宽松解析（`serde(default)`）。

## 三、最小节点的两种入网方式

**方式 A：文件搬运（离线优先，ESP32/无网设备）**
```
设备：写 ledger-<node>.jsonl  →  拷进 <domain>/ledger/   （U 盘 / TF 卡 / 蓝牙 / 下次插电脑）
宿主节点：learn-sync → 账本合并 → user.md 重算 → 设备下次同步时拿到新题与回执
```

**方式 B：直接调宿主（有网设备）**
```
设备 → 宿主：learn-queue（拿题）
设备 → 宿主：learn-answer（作答）
宿主 → 设备：该知识点的掌握度与下次复习时间（用于设备上的「今日错题」提示）
```

## 四、委托流对最小节点的意义

ESP32 只做**选择题 + 错题委托**：
1. 本地记录今天做错的题；
2. 生成 `wrong/<date>-<node>.md`（人读表格 + 机读 JSON 块）放进账号域；
3. 任一「会调模型」的节点处理它，写回执 `...result-<node>.md`；
4. 设备下次同步，把回执读回来展示（「另一台设备帮我看的错题」）。

**这样：算力强的一端负责生成与诊断，算力弱的一端负责高频练习与采集。** 二者地位相等，只是分工不同——这就是「对等是权利，专注是优化」。
