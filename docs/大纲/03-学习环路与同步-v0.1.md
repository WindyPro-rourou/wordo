# 学习环路与同步 v0.1（可执行规范）

> 本文是「环路」的落地规范。设计目标：**任何一台设备都能跑完整环路**；多设备之间靠「append-only 账本 + 派生状态」同步，**结构上不可能冲突**，也不需要主从。

## 一、账号域（Domain）目录

```
<domain>/                     # 账号域 = 一个可同步的目录（同步盘 / U 盘 / 局域网共享都行）
  node.json                   # 本机节点身份 { "node": "pc-a1b2" }
  settings.md                 # 个性化设置（随域同步）
  ledger/<node>.jsonl         # ★ 每节点一个 append-only 账本（事实来源）
  user.md                     # ★ 派生文件：学习者状态（谁都能从账本重算，因此无冲突）
  plan.md                     # 学习计划 / 任务清单（append-only 行）
  wrong/<date>-<node>.md      # 委托文书：今天的错题（A 设备写给域内其他设备）
  wrong/<date>-<node>.result-<byNode>.md   # 委托回执：其他设备处理后的结果
```

**为什么无冲突**：节点只**追加自己**的账本文件（`ledger/<自己>.jsonl`），从不改写别人的文件；`user.md` 是**派生**的（读全部账本重算），谁重算结果都一样。所以「同一账号域下的所有设备共享同一份学习状态」，而**没有主从**。

## 二、账本事件（append-only 事实）

一行一个 JSON。`kind` 决定语义：

| kind | 含义 | 关键字段 |
|---|---|---|
| `answer` | 一次作答 | item_id, kc_ids, answered, correct, ok, error_type, source(quiz/review/ai-followup) |
| `explain` | 展示了某 KC 的讲解 | kc_ids, source(material/ai), model |
| `plan_add` / `plan_done` | 任务清单增/完 | task_id, note |
| `delegation_out` | 导出错题委托 | file, count |
| `delegation_result` | 回执并入 | file, by_node, count |

```json
{"id":"1762...-pc-a1b2","ts":"2026-11-03T19:02:11+08:00","node":"pc-a1b2","kind":"answer",
 "pack":"english.high","item_id":"it_eng_0001","kc_ids":["kc_eng_0002"],
 "answered":"A","correct":"B","ok":false,"error_type":"none","source":"quiz"}
```

## 三、派生状态（user.md 由账本重算）

对每个知识点：

- `attempts / correct / wrong / streak`
- `mastery = Σ(okᵢ·wᵢ)/Σ(wᵢ)`，权重 `wᵢ = 0.5^(距今小时/72)`（72 小时半衰期——旧成绩会淡出）
- **已掌握**：`mastery ≥ 0.8 且 streak ≥ 2`
- **薄弱**：`wrong ≥ 1 且未掌握`

### 复习间隔（SM-2 简化）
- 答对：`streak=1 → 24h`；之后 `×2`（上限 30 天）
- 答错：`streak=0`，间隔 = `max(4h, 间隔/2)`（错题当天/次日必回炉）
- `due = last_ts + interval`；**due ≤ now 即进入今日复习队列**

### 出题优先级
① 最近答错的题 → ② 从未做过的题 → ③ 最久未做的题

## 四、环路（单机闭环）

```
到期队列/选 KC → 出题 → 作答 → 判分 → 错因(T1) → 写账本 →
      重算 user.md（薄弱点/掌握度）→ 下次到期 → 回到出题
```
关键：**每一步都写账本**，所以状态可重放、可审计（A3 变更留痕）。

## 五、跨设备环路（去中心化）

```
A 设备：今天错题 → wrong/<date>-A.md（委托文书）+ 账本 delegation_out
   ↓（同步盘 / 任意文件通道）
B 设备：扫描未回执的委托 → 调模型生成「错因+补讲+变式题」(T3) →
       写 wrong/<date>-A.result-B.md + 自己账本 delegation_result
   ↓
A 设备：下次同步读回执 → 并入本地账本 → user.md 里出现「其他设备帮我看的错题」
```
**没有主从**：任何设备都能发起委托（写错题文件），任何设备也都能处理别人的委托（写回执）。ESP32 单词机就是「只作答、只出委托」的最小节点。

## 六、规范三件套同步升级

新增任务 **T3 review-wrong（委托处理）**：
- `prompt-pack/1/PROMPT.md` → T3 规程

- `core/src/outcheck.rs` → T3 校验
一份文本两种消费：`user.md` 人读是学习档案，模型读是个性化上下文。
