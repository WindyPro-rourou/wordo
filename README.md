# WORDO · 去中心化分布式跨平台自进化 AI 学习系统

> **已发布 v1.0.0 的可运行产品**（tag `v1.0.0` · Release 已发布 · 默认分支 `master`）。
> 一台设备即可跑完整学习环路；多设备靠「append-only 账本 + 派生视图」同步，结构上不冲突。
> 仓库：<https://github.com/WindyPro-rourou/wordo>

---

## 一句话定位

**不是训练一个更大的模型，而是做一个「会记账的自进化学习系统」**——把每一次学习与 AI 的工作都变成带证据的经验，跨设备同步，并用可审计的账本证明它真的在变强。

产品形态是 **chat-first 学习终端**：侧栏是对话历史，第一句话自动判定学科，对话里就能「讲讲 XX / 出题 / 我该复习什么 / 判分」。

---

## 现在能做什么（v1.0 已交付）

- **对话式学习**：讲解、出题、判分、复习建议，全部内联在对话线程里；模型输出经正式 JSON Schema 校验后才呈现，注入该知识点讲解素材后首轮即通过校验。
- **学科自动判定**：第一句话按「知识点名 > 学科名 > 包 id > 简称」加权命中，用户可随时手动纠错（写事件、不改历史）。
- **会话历史**：新建 / 切换 / 删除（墓碑）/ 自动标题；会话按账号域存储，天然随域同步。
- **今日任务**：复习队列 → 薄弱点 → 学习计划 → 用户状态（user.md）→ 导出周报，一屏完成。
- **答题记账**：每道题（含讲解内嵌检测题）判完即写账本，带**置信度三档**与**错因分型**。
- **间隔复习**：错 → 4h；不确定对 → ×1.4；确定对 → ×2（上限 30 天）；蒙对按错处理；已掌握转 14 天以上低频抽查。
- **跨设备委托**：把今日错题导出为文书，账号域内另一台设备处理后写回执，主设备读回。
- **教师视图**：题库 / 知识树 / 校验报告（入口在设置页，是否对学生隐藏待定）。

三个页签：**对话 / 今日 / 设置**。

## 快速开始（从源码跑）

需要：Rust 工具链（跑 core 与桌面壳）、Node.js ≥ 20（跑预览或 Tauri CLI）。本机无 Rust 时可先只跑「无头预览」。

```powershell
# ① 构建 Rust 核心（CLI: wordo）
cd core
cargo build                       # 产物 target/debug/wordo；仓库内 .cargo/config.toml 可能把 target-dir 指到 C:/wordo-build/target

# ② 无需 Rust 的开发预览（真契约 Node 后端 + 系统 Edge 无头，读真实 packs/账本）
cd tools/preview
npm i
node seed.mjs                     # 造演示账号域
node server.mjs --port 4310       # 打开 http://127.0.0.1:4310

# ③ 桌面壳（需 Rust + MSVC + WebView2）
cd apps/desktop
npm install
npm run dev                       # = tauri dev（npm run build = tauri build 出安装包）
```

> 更细的步骤、首次使用三步（配模型 → 新建或选学科 → 开始学）与常见问题见 [docs/快速开始.md](docs/快速开始.md)。

## 架构总览

三端同构：桌面壳、CLI、开发预览共用**同一份 JSON 契约**（`core/src/api.rs`）。壳层只做呈现，不承载业务逻辑。

```
                   ┌────────────────────────────────────────────────┐
                   │                 壳（呈现层）                     │
                   │   桌面 Tauri 2   ·   手机 Tauri 2   ·   开发预览   │
                   └───────────────┬────────────────────────────────┘
                                   │  同一份 JSON 契约（list_packs / ask_model /
                                   │  learn_* / chat_* / detect_subject / export_report …）
             ┌─────────────────────┼───────────────────────┐
        Tauri 命令             CLI (wordo)           预览后端（Node 同契约复刻）
             └─────────────────────┼───────────────────────┘
                                   ▼
                   ┌────────────────────────────────────────────────┐
                   │        Rust core：契约与数据（core/src/api.rs）  │
                   │  validate · learn(账本) · chat · llm · outcheck  │
                   └───────────────┬────────────────────────────────┘
                                   ▼
                   ┌────────────────────────────────────────────────┐
                   │   数据：账号域目录（文本为源，放同步盘即同步）     │
                   │  ledger/<node>.jsonl · chats/<id>/ · user.md(派生) │
                   └────────────────────────────────────────────────┘
```

- **core = 契约与数据**：Rust 负责校验、账本、会话、模型调用、输出校验；不依赖具体 UI。
- **壳 = 呈现**：Tauri 命令只是一层薄封装；开发预览用 Node 复刻同一契约，测的就是真东西。
- **数据 = 账号域文本账本**：每个节点只追加自己的文件，视图（user.md / 计划 / 会话）都由账本派生。

详见 [docs/架构.md](docs/架构.md)。

## 多端与同步

- **Windows 桌面**：已支持（Tauri 2，WebView2 运行时）。
- **Android / iPadOS**：Tauri 2 移动端，已给出构建步骤与 SDK 要求，**尚未在本机实机构建**。见 [docs/多端构建指南.md](docs/多端构建指南.md) 与 [apps/mobile/README.md](apps/mobile/README.md)。
- **ESP32 单词机**：极简节点（只取题 / 写一行 JSON / 搬运文件）。协议与可运行参考实现见 [tools/mininode/README.md](tools/mininode/README.md)，固件草图见 [embed/esp32-node/](embed/esp32-node/)，设计见 [docs/大纲/04-节点接口与最小节点-v0.1.md](docs/大纲/04-节点接口与最小节点-v0.1.md)。

## 学习科学规则

| 规则 | 落地做法 |
|---|---|
| 置信度三档 | 作答时标注「确定 / 说不准 / 蒙」，参与调度与掌握度计算 |
| 蒙对不算掌握 | 蒙对按错处理（间隔 4h、连对清零），掌握度只计 15% |
| 看错题不降掌握 | 错因记为 `misread`（审题问题 ≠ 知识点没掌握），仍计入错题统计 |
| 已掌握低频抽查 | 掌握后间隔 ≥14 天，不占每日复习配额 |
| 错因分型 | 概念不清 / 算错 / 看错题，随答题落账；到期队列里「概念不清」优先 |
| 交错练习 | 「混合练 3 个薄弱点」→ 2–3 个知识点混排出题 |
| 换种讲法重讲 | 同一知识点连续两次答错 → 触发「换种讲法重讲」 |

## 跨模型一致性（口径与现状）

同一份正式 Schema（`specs/output-schema/1/`）+ golden 用例 + 度量脚本（`tools/consistency/`），对 explain / classify-error / review-wrong 三类任务度量。**如实说明口径**：

| 项 | 现状 | 说明 |
|---|---|---|
| 结构合规 | 5/5 + 5/5 通过 | **这是「门禁」不是「能力指标」**：Schema 约束下接近必过，掉下来说明 Prompt/解析被改坏 |
| 结构一致率（剔除主观字段） | 100% | 单轮单路由组采样，会随上游波动 |
| 全字段一致率 | 100%（本轮） | 同上，样本小 |
| 自一致性基线 | 100% | 同模型多次的噪声下限，用于对照 |

> 已知局限：主观字段（错因 / 置信度 / inferred）应当用**人工 golden + kappa** 度量，并对照自一致性噪声基线；本仓库目前只做到「结构门禁 + 单轮一致率」，这是**待补项**而非已达标。多模型评审的采纳/排期见 [docs/评审/2026-11-08-v1.1-多模型评审综合.md](docs/评审/2026-11-08-v1.1-多模型评审综合.md)，历史报告见 [docs/评审/一致性报告-2026-11-07.md](docs/评审/一致性报告-2026-11-07.md)。`auto/*` 是路由组，跨调用可能落到不同上游，多次采样会波动。
